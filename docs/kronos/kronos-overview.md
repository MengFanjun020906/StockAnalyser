# P-Kronos 买卖点建模方案解读

> 基于 AWS Applied Scientist Haoran Lv 的方案《Modeling Buy and Sell Points in BTC Intraday Trading》，结合本项目（kronos_hyper_sm）的实际实现进行梳理。

---

## 1. 方案全局架构

整套系统分为四个阶段：

```
K线获取 & 处理 → 买卖点打标 → 模型训练 & 部署 → 策略回测
```

- **打标阶段**（离线）：用"上帝视角"在历史数据上标注出理想买卖点，作为训练标签
- **训练阶段**：让模型学会只看历史K线就预测当前点的买卖类别
- **推理阶段**（在线）：模型只输入历史K线，输出 7 分类概率，不需要任何未来信息
- **回测阶段**：用简单交易策略验证模型信号的收益率

---

## 2. 打标算法：两个核心参数

打标是一个 **离线标注过程**，利用未来数据（实盘不可获取）找出历史上的最优买卖时机，为模型提供训练标签。

### 2.1 未来窗口（Future Window）

**含义**：从当前K线向未来看的一段范围，用于评估该点位的潜在收益/风险。

```python
# 伪代码
future_window = price_data[i+1 : i+window_size+1]
future_max = max(future_window)
future_min = min(future_window)

up_potential = (future_max - current_price) / current_price   # 潜在上涨幅度
down_risk   = (current_price - future_min) / current_price    # 潜在下跌风险
```

例如 "未来窗口24"（5分钟K线 × 24 = 2小时）：向未来看24根K线，找到这2小时内的最高/最低价，计算上涨潜力和下跌风险。只有超过阈值才触发信号。

**本项目对应**：`labeling.label_window_size`（`labeled_algo.py` 中的 `window_size`），使用 `FixedForwardWindowIndexer` 实现。

### 2.2 极值点窗口（Extreme Point Window / Fractal Window）

**含义**：用于判断当前价格是否是一个局部极值（局部最低=候选买点，局部最高=候选卖点）。

- 买点要求：当前价格 **低于** 前后各 N 根K线的价格（局部最低点）
- 卖点要求：当前价格 **高于** 前后各 N 根K线的价格（局部最高点）

例如 "极值点窗口12"（5分钟K线 × 12 = 1小时）：检查当前价格是否比前后各1小时的价格都低（买点）或都高（卖点）。

**本项目对应**：`labeling.label_fractal_window`（`labeled_algo.py` 中的 `fractal_window`），使用中心滚动窗口 `2 × fractal_window + 1` 实现。

### 2.3 两者的配合关系

以最佳实验配置 **"未来窗口24，极值点窗口12"** 为例：

| 参数 | 值 | 实际时间跨度 | 作用 |
|---|---|---|---|
| 极值点窗口 | 12根K线 | 前后各1小时 | **第一层筛选**：当前点必须是前后1小时内的局部极值 |
| 未来窗口 | 24根K线 | 向未来看2小时 | **第二层筛选**：未来2小时的涨跌幅必须超过阈值 |

打标流程：

1. 极值点窗口找出所有局部极值点（候选点）
2. 未来窗口评估每个候选点的潜在收益/风险是否超过阈值
3. 两个条件同时满足 → 标记为买/卖点
4. 贪心过滤算法去掉过于密集的信号（每个区间仅保留最佳点）

> **极值点窗口决定"这里是不是拐点"，未来窗口决定"这个拐点值不值得操作"。**

## 3. 模型方案：Classification Head（PDF 中称 HyperNetwork）

PDF 提出了三种将分类任务融入自回归模型的方案：

| 方案 | 思路 | 优点 | 缺点 |
|---|---|---|---|
| Option 1: Tokenization | 将标签P直接作为K线的第7维输入 | 简单，几乎不改代码 | 无法加载预训练权重；P只能看到过去信息 |
| **Option 2: HyperNetwork** | 在 Transformer 输出上附加分类头 | 解耦两个 loss；可加载预训练权重；兼顾前后信息 | 需要调 λ 平衡两个 loss |
| Option 3: GRPO | 用 GRPO 强化学习优化K线生成 | 对原始生成完全无影响 | 开发工作量大 |

**本项目主要实现的是 Option 2**，代码中叫 `classification_head` 而非 HyperNetwork。

### 3.1 核心原理

```
输入 K线序列 (OHLCVA)
       ↓
  Kronos Transformer（保持原架构不变）
       ↓
  取 central 位置的 hidden state
       ↓
  Classification Head (MLP + softmax) → 7分类预测
       ↓
  总 Loss = L_ar (K线生成) + λ × L_cls (分类)
```

`central` 位于 `lookback_window` 的最后一个位置。训练时，它既能通过 attention 看到前面的历史K线，也能通过 `predict_window` 获取后续K线的上下文，实现"前后兼顾"。

### 3.2 本项目的多个演进版本

| 文件 | 分类方案 |
|---|---|
| `model/kronos.py` | 基础版：last-token hidden state → MLP |
| `model/kronos_v2_0.py` | Attention pooling + Norm → MLP |
| `model/kronos_v3_0.py` | decision_state（历史决策点）→ MLP |
| `model/kronos_v3_2.py` | Query-token 方案（仅用历史信息的 query）→ MLP |
| `model/kronos_v3_4.py` | v3.0 + 可选对比学习 projection |

## 4. 标签体系设计：为什么数据均衡至关重要

这是 PDF 中最关键的实验发现之一。

### 4.1 标签体系1（3分类）→ 失败

```
0: 强买点 (Strong Buy)    ~14.2%
1: 中性 (Neutral)          ~78.8%  ← 极度不均衡
2: 强卖点 (Strong Sell)     ~7.0%
```

测试集结果（未来窗口24，极值点窗口12）：

| Class | Precision | Recall | F1 |
|---|---|---|---|
| 0 (强买) | 0.0621 | 0.2788 | 0.1016 |
| 1 (中性) | 0.9559 | 0.6114 | 0.7458 |
| 2 (强卖) | 0.0651 | 0.2146 | 0.0999 |

买卖点的 Precision 仅 **6%**，模型几乎无法区分买卖信号和中性信号。各种升降采样、loss 加权均无效。

### 4.2 标签体系2（7分类）→ 成功

```
0: 强买点 (Strong Buy)         ~14.2%   未来上涨 > 3倍平均波动
1: 弱买点 (Weak Buy)            ~1.6%   3倍 > 未来上涨 > 1.5倍
2: 中性偏多 (Neutral Bullish)   ~29.7%   1.5倍 > 未来上涨 > 1倍
3: 中性 (Neutral)                ~3.4%   未来波动 < 平均波动
4: 中性偏空 (Neutral Bearish)   ~32.6%   1.5倍 > 未来下跌 > 1倍
5: 弱卖点 (Weak Sell)            ~1.6%   3倍 > 未来下跌 > 1.5倍
6: 强卖点 (Strong Sell)          ~7.0%   未来下跌 > 3倍平均波动
```

测试集结果：

| Class | Precision | Recall | F1 | Correct/Total |
|---|---|---|---|---|
| 0 (强买) | 0.8292 | 0.6695 | 0.7408 | 1359/2030 |
| 1 (弱买) | 0.8571 | 0.7304 | 0.7887 | 168/230 |
| 2 (中性偏多) | 0.8816 | 0.8946 | 0.8880 | 6423/7180 |
| 3 (中性) | 0.6569 | 0.6767 | 0.6667 | 358/529 |
| 4 (中性偏空) | 0.8603 | 0.9316 | 0.8945 | 5376/5771 |
| 5 (弱卖) | 0.8125 | 0.6964 | 0.7500 | 156/224 |
| 6 (强卖) | 0.7494 | 0.6441 | 0.6928 | 655/1017 |

强买点 Precision 从 6% 跃升至 **83%**，提升立竿见影。

### 4.3 深层原因分析：问题不只是"数量不均衡"

**升降采样和 loss 加权为什么在标签体系1上全部失效？**

根本原因是 **标签定义本身导致类别在特征空间不可分**，而非模型"注意力分配不够"。

#### （1）Neutral 类内部方差过大

标签体系1 的 Neutral（78.8%）把截然不同的市场状态混为一谈：

```
Neutral 实际包含：
├── 微涨但不够"强买"阈值 → 本质偏买
├── 微跌但不够"强卖"阈值 → 本质偏卖
├── 横盘不动 → 真正中性
├── 先涨后跌相互对冲 → 看似中性但波动剧烈
└── 波动大但没碰到极值点 → 完全不同的 pattern
```

这些在特征空间中分布迥异的样本被强行归为同一个类，导致 Neutral 的决策边界极其混乱。

#### （2）过采样放大了边界噪声

Strong Buy 和 Neutral 的边界样本在特征空间几乎重叠（只差一点点阈值）。过采样复制/合成更多少数类样本，本质上是放大了这种边界噪声，模型更难找到干净的决策边界。

#### （3）Loss 加权导致过拟合噪声边界

给 Strong Buy/Sell 更高的 loss 权重，模型会更拼命地试图分开两个在特征空间重叠的类别，最终过拟合到训练集的噪声边界，测试集 Precision 反而暴跌。

#### （4）标签体系2 为什么有效

标签体系2 的成功 **不是因为"更均衡"，而是因为标签定义更合理**：

- **硬切分 → 软渐变**：`强买 → 弱买 → 中性偏多 → 中性 → 中性偏空 → 弱卖 → 强卖`，平滑过渡
- **类内一致性提高**：每个类的样本在特征空间更聚拢，决策边界更清晰
- **边界样本有了正确归属**："差一点就是买点" 归入 "弱买" 而非被强行塞进 "中性"
- **序数结构（ordinal structure）**：7个类有天然顺序，即使预测错了也不会错得太离谱
- **对交易策略更友好**："强买" 和 "弱买" 之间的混淆不影响交易方向，只影响仓位权重

> **结论：均衡是表象，合理的标签定义才是本质。** 升降采样和 loss 加权能解决"模型注意力分配"问题，但无法解决"标签定义导致类别不可分"的根本矛盾。

## 7. 关键结论

1. **打标是"上帝视角"标注**：利用未来数据找历史最优点，教模型学会"事前预判"
2. **极值点窗口 + 未来窗口 双重筛选**：前者找拐点，后者评估拐点价值
3. **分类头（HyperNetwork）方案最优**：解耦生成 loss 和分类 loss，可加载预训练权重
4. **标签体系设计 > 采样/加权技巧**：7 分类的细粒度标签从根源上解决了类别不可分问题
5. **市场存在周期性**：测试集外效果下降，模型需要周期性重新训练
