# 模型与训练器迭代演进

---

## 前置知识

Kronos 模型同时做两件事：

1. **K线生成**（主任务）：自回归预测下一根K线的 token
2. **买卖点分类**（附加任务）：预测当前点属于 7 类中的哪一类（强买/弱买/.../强卖）

总 loss = K线生成 loss + λ × 分类 loss

训练时，模型输入的序列包含两段：

```
[  历史K线 (lookback_window)  |  未来K线 (predict_window)  ]
                              ↑
                     标签取这个位置（决策边界）
```

所有版本共享同一个生成骨架（RoPE Transformer），区别在于**分类头怎么设计、怎么训练**。

---

## v_default / v3.0 — 基线

**目标**：在 Kronos 上建立买卖点分类的基线方案。

### 模型做了什么

取序列中"历史最后一个位置"的 hidden state，喂给一个简单 MLP 做 7 分类：

```
序列：[h₁, h₂, ..., h_lookback, f₁, f₂, ..., f_predict]
                         ↑
              取这个位置的 hidden state → Linear → ReLU → Dropout → Linear → 7类
```

### 训练做了什么

- 默认训练器 `predictor_default`
- Loss = token CE + λ × classification CE（分类 loss 未加权）
- AdamW 优化器，支持分类头和骨架分别设置学习率
- 计算了类别逆频率权重，但**实际未启用**

### 存在的问题

1. **训练/推理不一致**：训练时决策位置取的是 `seq_len − predict_window − 1`，推理时 `classify()` 取的是最后一个 token，两者不一定对齐
2. **因果 attention 的限制**：决策位置在因果 mask 下只能看到之前的历史K线，看不到之后的未来K线，但标签本身是基于未来数据生成的
3. **强买/强卖表现差**：这两个最重要的类在数据中占比小，默认训练器没有针对性优化

---

## v2.0 — 注意力池化

**目标**：让分类头能聚合整个序列的信息，而不是只看一个固定位置。

### 模型做了什么

用 Multi-Head Attention 对整个序列做全局池化，替代固定位置取值：

```
序列：[h₁, h₂, ..., h_lookback, f₁, f₂, ..., f_predict]
       └─────────── Attention 池化 ───────────┘
                          ↓
              加权聚合的全局向量 → RMSNorm → MLP → 7类
```

Query = 序列所有位置的均值，Key/Value = 所有位置。通过 attention 自动学习该关注哪些位置。

### 训练做了什么

复用默认训练器，无训练侧改动。

### 相比 v3.0 解决了什么

分类头不再局限于单一位置，能综合全局信息。

### 引入了什么新问题

训练时 attention 能看到未来K线（因为未来K线在序列中），推理时看不到。**训练和推理看到的信息不一致**，导致泛化性存疑。

---

## v3.0 + focus_v1 训练器 — 聚焦训练

**目标**：不改模型结构，通过训练策略提升模型在强买/强卖上的表现。

### 模型做了什么

和 v3.0 完全相同，无架构变化。

### 训练做了什么

使用专用训练器 `train_predictor_v3_0_focus_v1`，四个改进：

1. **聚焦采样**：训练时对强买（0）和强卖（6）的样本过采样，通过 `focus_labels` + `focus_multiplier` 控制倍率，让模型更频繁地看到这些关键样本
2. **加权 CE Loss**：按类别频率设置 loss 权重 + 可选 label smoothing
3. **聚焦指标驱动**：
   - 早停基于 `val_focus_f1_mean`（只看强买/强卖的 F1），而非全类别指标
   - 学习率调度也基于聚焦指标
   - 保存 `best_focus_f1_model` 检查点
4. **验证集稳定**：验证集固定顺序采样（`strategy: index`），避免随机采样导致验证指标波动

### 相比纯 v3.0 解决了什么

在不改架构的前提下，让训练过程更关注最重要的两个类别，提升强买/强卖的 Precision 和 F1。

### 存在的问题

聚焦采样本质上是过采样，对于类别边界模糊的样本（弱买 vs 中性偏多）帮助有限——嵌入空间中这些类别仍然可能混在一起。

---

## v3.2 — Query Token

**目标**：从架构层面解决训练/推理不一致问题。

### 模型做了什么

在序列末尾追加一个**可学习的 query token（Q）**，通过定制 attention mask 确保 Q **只能看到历史部分，看不到未来部分**：

```
序列：[h₁, h₂, ..., h_lookback, f₁, f₂, ..., f_predict, Q]
       └── Q 可以 attend ──┘    └── Q 不能 attend ──┘   ↑
                                                    取 Q 的输出 → MLP → 7类
```

- Q 的 RoPE position_id 与历史最后一个位置相同（位置语义对齐）
- Attention mask 显式阻止 Q 看到未来 token
- 生成任务仍使用完整序列（不含 Q），两个任务互不干扰

### 训练做了什么

使用 `train_predictor_v3_2`，本质是默认训练器的薄包装：只额外处理了从旧检查点加载时 `query_token` 和 `classification_head` 的初始化问题，训练逻辑完全复用默认训练器。

### 相比之前版本解决了什么

**训练和推理完全一致**：Q 在两种场景下看到的信息完全相同（只有历史K线）。不像 v_default 训练/推理位置不一致，也不像 v2.0 训练时能看到未来而推理时看不到。

### 存在的问题

- `classify()` 推理时必须跑完整个 `forward`（Q 要参与 attention），不能复用纯解码的 context，推理开销略大
- 训练策略仍是默认的，没有像 focus_v1 那样针对强买/强卖做聚焦优化

---

## v3.4 — 对比学习（SupCon）

**目标**：用监督对比学习改善分类特征空间的结构化程度，让同类样本更紧凑、异类样本更分散。

### 模型做了什么

在 v3.0 的基础上，新增一个**对比学习投影头**（MLP → L2 归一化），输出一个低维嵌入向量用于对比学习。分类头保持不变：

```
决策向量 (v3.0 方式取得)
    ├── → MLP 分类头 → 7类 logits  （和 v3.0 完全相同）
    └── → 对比投影头 → L2 归一化    （新增，仅训练时使用）
```

推理时只用分类头，投影头不参与。

### 训练做了什么

使用 `train_predictor_v3_4`，在默认训练器上增加 SupCon loss：

**总 loss = K线生成 loss + λ₁ × 分类 CE loss + λ₂ × SupCon loss**

SupCon 的做法：
- 同一 batch 中，相同标签的样本互为正样本对，不同标签的为负样本对
- 优化目标：正样本对的嵌入距离拉近，负样本对推远
- 支持 DDP 多卡 global gather（跨 GPU 收集更多正负样本对）
- 可选 `focus_only` 模式：只用强买/强卖作为对比锚点，减少中性类噪声

### 相比之前版本解决了什么

分类 CE loss 只优化决策边界，不关心类内是否紧凑。SupCon 额外约束了嵌入空间的结构：

| | 纯 CE | CE + SupCon |
|---|---|---|
| 同类样本 | 可能分散在决策边界同一侧的任意位置 | 被拉拢到一起 |
| 异类样本 | 只要在边界另一侧即可 | 被推远到足够远 |

对于边界模糊的类别（如弱买 vs 中性偏多），嵌入空间更有结构后分类更准。

### 存在的问题

- SupCon 对 batch size 敏感：batch 太小时同类样本对不够，loss 信号弱
- 超参数多（对比权重 λ₂、投影维度、温度参数等），调参成本高
- 决策向量仍用 v3.0 的固定位置取法，训练/推理一致性问题仍在

## 各版本一览

| 版本 | 一句话概括 | 模型改动 | 训练改动 | 解决了什么 |
|---|---|---|---|---|
| **v3.0** | 基线 | 固定位置 + MLP | 默认 CE | 在 Kronos 上建立分类能力 |
| **v2.0** | 全局池化 | Attention 池化 | 默认 CE | 聚合全局信息 |
| **v3.0 + focus** | 聚焦训练 | 无变化 | 聚焦采样 + 加权 CE + 聚焦指标 | 提升强买/强卖表现 |
| **v3.2** | Query Token | 可学习 Q + attention mask | 默认 CE + 初始化适配 | 训练/推理一致性 |
| **v3.4** | 对比学习 | v3.0 + 投影头 | CE + SupCon | 特征空间结构化 |

### 演进路线

```
v3.0（基线）
  │
  ├─→ v2.0（尝试全局池化 → 发现训练/推理不一致）
  │
  ├─→ v3.0 + focus_v1（不改架构，通过训练策略聚焦关键类别）
  │
  ├─→ v3.2（从架构上解决训练/推理一致性）
  │
  └─→ v3.4（从 loss 上强化嵌入空间结构）
```

这些方向并非线性替代关系，而是**从不同角度优化同一个系统**：v3.2 解决的是架构一致性，focus_v1 解决的是训练关注度，v3.4 解决的是特征空间质量。理论上可以组合使用。

## 各版本合理性评估

五个版本从原理和方案可行性上**都是合理的探索**，每个版本针对一个真实存在的问题，采用的技术手段也都有理论支撑和业界先例：

| 版本 | 针对的问题 | 方案合理性 |
|---|---|---|
| **v3.0** | 需要一个基线 | 最简单的做法（固定位置 + MLP），是标准起点 |
| **v2.0** | 单位置信息可能不够 | 用 attention 聚合全局信息是自然的想法。虽然发现了训练/推理不一致，但这恰恰是通过尝试才能发现的，直接催生了 v3.2 |
| **focus_v1** | 强买/强卖表现差 | "不动架构、先从训练策略入手"是工程上最务实的路径——改训练比改模型成本低、迭代快。力度过猛是调参问题，不是方向问题 |
| **v3.2** | 训练/推理不一致 | 可学习 query token + attention mask 是成熟做法（类似 BERT [CLS]、DETR learnable query），且把分类和生成在架构上解耦了 |
| **v3.4** | 嵌入空间缺乏结构 | CE loss 只管"分对不分错"，SupCon 让同类拉近、异类推远，对边界模糊类别有理论依据 |

### 已知不足与可能的改进方向

**1. v3.4 继承了 v3.0 的训练/推理不一致**

v3.4 基于 v3.0 而非 v3.2，决策向量仍用固定位置取法。对比学习学到的嵌入空间结构是基于不一致的决策向量，泛化性可能打折扣。自然的下一步是 **v3.2 + SupCon**：在 Query Token 输出上做对比学习。

**2. 各版本从未交叉组合验证**

v3.2（一致性） + focus_v1（训练关注度） + SupCon（嵌入质量）解决的是不同维度的问题，理论上可以叠加。但目前是平行探索，没有组合实验。

**3. 双任务梯度冲突未被显式处理**

token 生成和分类共享同一个 backbone，但两个任务的梯度方向可能冲突。从 v3.0 日志看，Val Token Loss 只涨了 7%，Val Class Loss 涨了 4 倍——分类任务的恶化速度远超生成任务，说明 backbone 被生成任务的梯度主导。可能的改进：

- **两阶段训练**：先只训生成，再冻结 backbone 只训分类头。避免梯度冲突，实现简单（改 config 即可）
- **动态任务权重**：让 λ 根据各任务 loss 的不确定性自动调节，而非固定值

**4. 层次化分类可降低任务难度**

当前直接做 7 分类。可以分解为：先判方向（看多/中性/看空，3 分类，相对均衡），再判强度（强/弱，2 分类）。更简单的子任务可能更容易学好，且方向判对但强度判错的代价较小。
