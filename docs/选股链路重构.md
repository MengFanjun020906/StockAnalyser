  选股链路重构设计方案

  0. 核心思路:把架构翻转过来

  现在的链路是 "确定性种子池 = 候选清单,专家贴标签"。
  目标架构是 "种子池 = 宽召回,专家 = 真正的选股决策者,汇总器 = 可审计的打分大脑"。

  一句话:种子池负责"别漏",专家负责"挑得准",汇总器负责"排得对",深入探究负责"按 setup 
  深挖一只"。

  ---
  1. Layer 0 — 种子池(召回层)

  定位从"候选清单"降级为"高召回、低精度的原料"。保留多源确定性召回的骨架(它没问题),做 4
  处改动:

  1.1 重新定义种子门的职责。
  现在 SEED_GATE_TRIGGER_THRESHOLD=30 导致门经常空转,"压缩到12"常常没生效。新定位:种子门不再
  产出"最终12",而是给专家喂一个可处理的集合(比如确定性预排序后取 Top
  24-30)。最终精筛交给专家,不再由一个无工具 LLM 噪音门拍板。

  1.2 修正 priority_score 跨源不可比。
  screener 分 / moneyflow rank / alphasift 因子分 / sequoia
  形态分量纲不同,直接同池排序有系统性偏差。改为:每个 source 内部先归一化成分位(0-1)或
  within-source rank,跨源只比分位,不比原始分。每个种子带上 source + normalized_rank。

  1.3 两类目标做硬配额。
  设计文档要求"强势延续 + 低位启动"都要保留,现在靠 source
  多样性自然覆盖、很脆。改为:给每个种子打 setup_hint(strength / low_base /
  neutral),喂给专家时保证两类都有名额(例如低位类至少保底 N 个),不让强势种子全挤占。

  1.4 种子携带"位置/拥挤"元数据。
  这是后面汇总器算 position/timing/crowding 的原料,必须在召回阶段一次性算好,避免下游重复拉数
  据:60/120日区间位置、近5日涨幅、距MA20/60乖离、量比、距20/60日高点距离。

  ---
  2. Layer 1 — 专家委员会(专家驱动选股)

  这是"翻转"的核心。两个关键改动:

  2.1 专家从"标注者"变成"门控者"。
  现在 _merge_capital_evidence 只把 evidence attach 到种子上,种子自动是候选。新规则:

  ▎ 一个种子只有被 ≥1 个专家给出 support/watch(且带工具证据)才进入 L1
  ▎ 候选;没有任何专家认领的种子,降级到观察池,不进 L1。

  这才是"专家驱动"——专家决定谁进、谁出,而不是种子自动晋级。

  2.2 专家梯队(分批扩,不一次上6个)。
  对照 选股池多专家设计.md 的6专家愿景,按边际价值排优先级:

  ┌──────────┬─────────────────────────────────────────┬──────┬──────────────────────────┐
  │   批次   │                  专家                   │ 现状 │           价值           │
  ├──────────┼─────────────────────────────────────────┼──────┼──────────────────────────┤
  │ 已有     │ capital_flow / early_turn               │ ✅   │ 资金 + 低位拐点          │
  ├──────────┼─────────────────────────────────────────┼──────┼──────────────────────────┤
  │ 第一批补 │ technical(趋势/结构) /                  │ ❌   │ 强势延续 +               │
  │          │ sector_theme(板块强度/补涨)             │      │ 题材补涨的主力判断       │
  ├──────────┼─────────────────────────────────────────┼──────┼──────────────────────────┤
  │ 第二批补 │ fundamental(质量/估值修复) /            │ ❌   │ 支撑 quality_repair /    │
  │          │ news_event(公告/事件)                   │      │ 排雷                     │
  └──────────┴─────────────────────────────────────────┴──────┴──────────────────────────┘

  每个专家维持:工具白名单 + bounded loop(现在5轮/10调用)+
  模式A(从种子筛)/模式B(种子空时自主发现)+ 只给 stance+evidence、不给
  score/confidence(沿用现规则)。

  2.3 汇总器变成"可审计的打分大脑"(重写 _committee_candidate_score)。
  现在打分太薄(只有共振+stance惩罚),且你 commit 提到的"工具覆盖率替换
  confidence"代码里其实没落地。新汇总器全部用确定性公式 + 上游证据/位置元数据计算,不让 LLM
  出分:

  confidence   = 已被工具验证的维度数 / 期望维度数   ← 落地"工具覆盖率替换LLM confidence"
  setup_type   = 由"哪些专家支持 +
  位置元数据"派生(early_turn/trend_continuation/capital_momentum/quality_repair/theme_follow)
  score = base(种子归一化分位)
        + resonance_bonus      # 多专家共振
        + position_score       # 位置是否还有空间(来自1.4元数据)
        + timing_score         # 是否已出现启动信号
        + asymmetry_score      # 上行/下行赔率
        - crowding_penalty     # 追高/拥挤
        - conflict_penalty     # 资金强+基本面弱等冲突
        - risk_penalty         # 硬风险

  我要提醒的两个坑:
  - 这套公式常数多、易过拟合。建议常数全部进
  config_registry,默认值给一套,留待历史回放调参,而不是写死在代码里凭感觉。
  - 6专家 × (多轮LLM + 10工具调用)并行,成本/延迟会显著上升。建议:专家只跑在种子门喂进来的 Top
   24-30 上;technical/sector 这类可先用确定性指标预判,只有边界情况才上 LLM。这条要你权衡。

  3. Layer 2 — 深入探究(补你的另外 50%)

  你的 50%:"选股的问题需要更精细的 prompt,不能由一个 system prompt 推断"。
  我补的 50%:按 setup_type 路由到不同"打法手册(playbook)",共享输出骨架、替换判断内核。

  3.1 结构:固定骨架 + 可变内核

  保持现有输出 schema(action_bias/entry_quality/dimension_summary/...)完全不变,这样下游
  allocation/adversarial/judge 不用动。
  只替换 prompt 中间那段 "分析指令 + 判定标准 + 失败/止损定义 + 入场逻辑" —— 由一个
  deep_dive_router(candidate) 按 setup_type 选 playbook 拼装。

  deep_dive_prompt =
      shared_header(角色/边界/行情口径/复用证据说明)
    + playbook_block[setup_type]      ← 精细化的核心,每种 setup 一套
    + market_block[cn|hk|us]          ← A股专属(涨停/龙虎/北向)与港美剥离
    + reused_evidence_block           ← 灌入上游专家证据,只补缺口不重拉
    + shared_output_schema

  3.2 五套 playbook(每套问不同的问题、定不同的失败/止损)

  setup: early_turn 低位启动
  核心论点(必须证伪): 拐点成立且未透支
  必查证据: 低位证据 + 转强信号(站均线/首次放量/回踩不破)+ 资金由负转正
  入场/止损逻辑: 入场=回踩不破平台或放量确认;止损=平台下沿/启动低点
  主要警惕: 抄在下跌中继、假突破
  ────────────────────────────────────────
  setup: trend_continuation 强势延续
  核心论点(必须证伪): 趋势健康、有舒服回踩位、未追高
  必查证据: 趋势结构 + 均线多头 + 乖离/RSI过热检查 + 回踩位
  入场/止损逻辑: 入场=回踩MA/突破回踩;止损=突破位/趋势线
  主要警惕: 追高、拥挤、次日分歧
  ────────────────────────────────────────
  setup: capital_momentum 资金/连板
  核心论点(必须证伪): 资金承接真实、非诱多
  必查证据: 主力净流入持续性 + 龙虎榜结构 + 封板强度/开板 + 连板高度
  入场/止损逻辑: 入场=竞价/分歧转一致;止损=破封板成本/首板低点
  主要警惕: 高位板、诱多、开板
  ────────────────────────────────────────
  setup: quality_repair 质量修复
  核心论点(必须证伪): 业绩/景气改善且估值未透支、价格滞后
  必查证据: 盈利质量/亏损收窄 + 估值位置 + 行业景气 + 价格滞后证据
  入场/止损逻辑: 入场偏价值、容忍慢;止损=基本面逻辑破坏(非纯技术)
  主要警惕: 价值陷阱、估值已透支
  ────────────────────────────────────────
  setup: theme_follow 题材补涨
  核心论点(必须证伪): 板块强且个股为有效补涨
  必查证据: 板块强度 + 个股相对板块位置(龙头已涨/二线未涨)+ 资金是否流向二线
  入场/止损逻辑: 入场=板块回踩企稳;止损=板块走弱
  主要警惕: 纯跟风、板块见顶

  ▎ 缺省:setup_type=unknown 时落到一个保守的通用 playbook(接近现在的6维模板)。

  3.3 顺手解决现 prompt 的 3 个老问题

  - failure_condition vs stop_loss 解耦:每套 playbook 明确区分——failure_condition=论点被证伪(
  可非价格,如"资金只持续一天"),stop_loss=价格风控线。两者都要,且 prompt 解释差异。
  - 复用上游证据:把 balanced_candidate_evidence + 专家 evidence 灌进去,prompt
  明确告知"哪些维度已有数据",深入探究只对缺口/过期维度调工具,不重拉全部(现在会重复取证)。
  - 市场专属逻辑剥离:涨停/龙虎/北向放进 market_block[cn],港美走各自
  block,不再硬编码进通用模板。

  重新设计:先把"病根"说清楚

  病根:你把两件本质不同的事,都叫成了"选股"

  一个选股系统里有两种根本不同的操作:

  ┌──────────────┬──────────────────────────┬───────────────────────────────┐
  │              │       召回 / 生成        │          判断 / 鉴别          │
  ├──────────────┼──────────────────────────┼───────────────────────────────┤
  │ 问题         │ 5000只里,哪些值得看一眼? │ 这一只到底好不好、是什么机会? │
  ├──────────────┼──────────────────────────┼───────────────────────────────┤
  │ 性质         │ 宽、便宜、可复现、高召回 │ 深、贵、有观点、高精度        │
  ├──────────────┼──────────────────────────┼───────────────────────────────┤
  │ 衡量         │ 有没有漏掉好票           │ 选出来的准不准                │
  ├──────────────┼──────────────────────────┼───────────────────────────────┤
  │ 该不该有观点 │ 不该。只认信号,不下判断  │ 必须有。这就是它存在的理由    │
  └──────────────┴──────────────────────────┴───────────────────────────────┘

  你现在的痛点本质是:种子池(AlphaSift/Sequoia/screener)已经在做"判断"了——它不是在"召回值得看
  的票",而是在用策略"挑出它认为好的票(优势股)",还排了序、打了分。于是 LLM
  专家接手时,好票已经被挑完、排完了,专家无事可做,只能贴标签。这就是你说的"专家层作用被忽视"。

  结论:不是专家层设计错了,是种子池越界,把判断的活儿干了,把专家的饭碗端了。

  更深一层:连"多维度专家 + 共振打分"这个框架本身,都跟你的目标相悖

  你的目标是 "低位买入,后面更容易涨"。但你设计的
  _committee_candidate_score(committee.py:1847)给 capital + early_turn 共振 +12
  分——也就是奖励那些"资金和低位信号同时亮"的票。

  可是:一个干净的低位启动票,按定义资金还没进来(进来了就不叫低位启动了,叫已经启动)。所以共振打
  分会系统性地给最好的低吸点扣分,给已经被市场发现、已经拥挤的票加分。

  这是"多维度专家 + 共振融合"这个范式的内在缺陷:它假设"越多维度同时叫好 = 
  越好",而这恰恰是追高的逻辑,不是低吸的逻辑。 你越往这个框架投入(扩到6个维度专家、做更复杂的
  resonance 汇总器),离你的目标越远。

  所以我这次不建议你走"6个维度专家 +
  富汇总器"——那是我上一版顺着你文档说的,现在我认为那个方向错了。

  新架构:召回 / 判断 彻底分家,而且按"打法"切专家,不按"维度"切

  核心三个动作

  1. 策略 → 特征(把种子池的"判断"权力收回来)

  AlphaSift / Sequoia / screener
  不再是"选好票的策略",降级为特征探测器。它们只回答可证伪的事实:
  - "这只票今天放2倍量破了20日高点"(特征,客观)
  - "RPS 进市场前10%"(特征,客观)
  - 而不是"这只票好,signal_score 87"(判断,主观)

  种子池的产出 = 一份带特征标签 +
  廉价预算指标(位置/量价/资金标志)的股票清单,只做硬排除(ST/退市/停牌)和去重。它的 KPI 变成召
  回率(别漏),不再排序、不再打分、不再分优劣。这一刀,种子池和专家的活儿就物理上不可能重叠了。

  2. 专家按"投资打法(thesis desk)"切,不按"数据维度"切

  放弃"资金专家/技术专家/基本面专家"。改成几个交易席位,每个席位是一套完整的选股逻辑,跨维度自
  洽:

  ┌─────────────┬─────────────────────────┬──────────────────────────────┬────────────────┐
  │    席位     │       它要找什么        │       它眼里"好"的标准       │    失败定义    │
  ├─────────────┼─────────────────────────┼──────────────────────────────┼────────────────┤
  │ 低位启动席  │ 跌透了、刚出现转强拐点  │ 位置低 + 首次转强 +          │ 跌回平台下沿   │
  │             │                         │ 资金刚由负转正(不是已流入)   │                │
  ├─────────────┼─────────────────────────┼──────────────────────────────┼────────────────┤
  │ 强势延续席  │ 趋势健康、有舒服回踩位  │ 不追高 + 回踩位明确 +        │ 跌破突破位     │
  │             │                         │ 量价不透支                   │                │
  ├─────────────┼─────────────────────────┼──────────────────────────────┼────────────────┤
  │ 资金/连板席 │ 资金承接真实、非诱多    │ 封板强度 + 龙虎结构 +        │ 破封板成本     │
  │             │                         │ 连板高度可控                 │                │
  ├─────────────┼─────────────────────────┼──────────────────────────────┼────────────────┤
  │ 质量修复席  │ 业绩/景气改善但价格滞后 │ 估值未透支 + 盈利改善 +      │ 基本面逻辑破坏 │
  │             │                         │ 价格没反映                   │                │
  └─────────────┴─────────────────────────┴──────────────────────────────┴────────────────┘

  为什么这个切法解决你所有痛点:
  - 不再重叠:种子池给"事实特征",席位做"打法判断"。低位启动席判断"这个放量站均线是真启动还是下
  跌中继"——这是种子池永远做不了的判断。
  - 不需要脆弱的共振汇总器:每个席位自己就是一个完整观点,不用把6个维度碎片再拼起来。
  - setup_type 不用"派生",它天生就是"哪个席位选的"。
  - 直接服务你的目标:低位启动席专门保护那些会被共振打分杀掉的低吸点。资金没进来,在低位启动席
  里是加分项(蓝海),不是扣分项。

  3. 跨席位不打统一分,而是按"市场状态"分配名额

  这是真实多策略基金的做法,也是你"priority_score
  跨源不可比"问题的根治:永远不要把低位启动的分和连板的分放一起比。改成:
  - 每个席位只在自己内部排序,各交出 Top 3-5。
  - 组合配置阶段按 market_regime
  决定每个席位给几个名额:进攻市多给资金/延续席,震荡/防守市多给低位/质量席。

  这样既消灭了跨源不可比,又让系统随市场自适应,而不是靠一个写死的全局公式。

  新的链路全貌

  全市场
    → 召回层(特征探测器:策略降级为特征 + 廉价指标 + 硬排除 + 去重)   ←
  只认信号,不下判断,KPI=召回
    → 各打法席位并行判断(低位启动/强势延续/资金连板/质量修复)        ←
  唯一的判断层,有权拒绝/重排,跨维度自洽
        每席位:从召回清单里挑符合本打法的 + 用本席位工具核实 + 内部排序出 Top N
    → 组合配置按 regime 分配各席位名额(不打统一全局分)
    → 深入探究:按席位 playbook 把"该打法的论点"压到可执行深度(进场/止损/失效/赔率)
    → adversarial → judge

  召回层 → 席位 → 深入探究 现在是一条 "事实 → 打法判断 → 可执行性"
  的漏斗,每一层做上一层做不了的事,没有任何重叠:
  - 召回:这只票有哪些客观特征?
  - 席位:这些特征构成哪种打法的机会吗、值不值得深挖?(广度,每席位3-5只)
  - 深入探究:既然是X打法,现在能不能执行、怎么执行?(深度,只在幸存者上做)

  深入探究和席位不再冗余——席位是"够不够格当X类候选",深入探究是"既然是X类,此刻可不可执行"。这
  也正好接上你要的"精细化 prompt":playbook 就是席位打法的执行级展开,一个席位一套,不再用一个
  system prompt 推断所有情况。

  关于"共识":你的直觉对,但要用对地方

  你说的是:各席位各判各的,没有一个共同的底线/共识(比如"资金是不是在流入、技术面是不是看多"),
  怕选出来的票各说各话、质量参差。这个担心是对的。

  但这里有个致命的坑,正是上一轮我们要躲开的那个:

  ▎ 如果把"共识"定义成 "每只票都必须资金流入 + 技术看多",你就亲手把低位启动席杀死了。
  ▎ 因为一个干净的低位启动票,按定义资金还没进来、技术还没走多头——它正处在"刚转强"的中性偏多状
  ▎ 态。要求它"资金流入+技术看多",等于只要那些已经启动、已经走强的票,你又回到追高了。

  所以解法不是"取消共识",而是把共识用在正确的方向上。一句话:

  共识用来"否决",不用来"加分"

  ┌────────────┬────────────┬───────────────────────────────────────────────────────────┐
  │            │ 该不该全局 │                           例子                            │
  │            │    统一    │                                                           │
  ├────────────┼────────────┼───────────────────────────────────────────────────────────┤
  │ 看空否决线 │ ✅ 全席位  │ 主力恶性放量出逃、有效跌破关键支撑且在加速下跌、ST/退市/  │
  │ (红线)     │ 共享、绝对 │ 停牌/重大利空未澄清、流动性不足                           │
  ├────────────┼────────────┼───────────────────────────────────────────────────────────┤
  │ 看多确认标 │ ❌         │ 低位席:刚转强即可;动量席:要资金承接;质量席:要业绩改善     │
  │ 准         │ 各席位自定 │                                                           │
  └────────────┴────────────┴───────────────────────────────────────────────────────────┘

  这是非对称的:
  - 看空是共识——不管哪个席位选的,只要踩了红线,一律否决。这就是你要的"底线"。
  - 看多是分歧——"够不够好"由各席位按自己的打法定,不强求所有维度都叫好。

  把你的两个例子精确化一下,你就看出区别了:
  - ❌ "资金流入"(确认要求)→ 杀死低吸 → 改成 ✅ "资金没有在恶性流出"(否决线)。低位席的票资金
  中性/微弱也能过,但资金正在夺路而逃的票,任何席位都别想选。
  - ❌ "技术面看多"(确认要求)→ 杀死低吸 → 改成 ✅ "没有处在破位加速下跌中"(否决线)。

  这样既给了你想要的"统一质量底线",又完全不伤低位启动。

  这个"共识"长在哪:共享事实底表(Fact Sheet)

  你担心"各专家各判各的",根子在于它们没有看同一份事实。真实的研究台是这样运作的:所有分析师看
  同一个 Bloomberg 
  终端(事实一致),但对怎么解读各有观点(判断分歧),而合规红线是绝对的(否决一致)。

  所以我在召回层和席位之间,加一个轻量的
  共享事实底表——这正好是召回层"特征库"的自然延伸,确定性计算,每只票算一次:

  baseline_fact_sheet(每只候选,确定性,只陈述事实不下判断):
    - 资金方向:主力净流入/流出/中性 + 是否恶性放量出逃
    - 趋势状态:多头/中性/空头 + 是否破位加速下跌
    - 位置:60/120日区间分位、距前高距离、近5日涨幅
    - 流动性:成交额是否达标
    - 硬风险:ST/退市/停牌/利空旗标
    - 板块/题材:所属板块强弱(这就是你的"题材"——见下)

  它有两个用途,正好解决你两个担心:
  1. 喂给每个席位当统一输入 → 各席位在同一份事实上做判断,不再各拉各的、各说各话。
  2. 作为共享否决门(veto gate)的依据 → 任何席位的选票,踩了红线就被确定性地拿掉或重降级。

  ▎ 注:题材/板块我建议不单独设席,而是放进这张底表当共享上下文——它同时给动量席(板块强助攻)和低
  ▎ 位席(板块补涨逻辑)用,独立成席反而又制造重叠。这点你认可吗?

  那"各席位判断冲突"怎么收口?——分三层,别用一个公式

  你怕的"没达成共识"会以两种形态出现,分别在不同地方收口:

  1. 踩红线的票 → 共享否决门确定性拿掉。(无需讨论,事实说话)
  2. 某席位的论点与事实底表矛盾(例:动量席说"资金驱动",但底表显示资金其实净流出)→ 打
  conflict_risk 标记,不静默保留,强制带着这个矛盾进深入探究,让深挖去裁决。
  3. 多席位同时选中同一只票(且方向一致)→
  这才是真正的强共识,是好事,直接给它更高的深挖优先级。注意:这跟旧的"共振加分"不同——这里是两套
  独立打法不约而同(真信号),而不是"同一只票在6个维度上都亮"(拥挤幻觉)。

  关键:不在席位汇总阶段用数字公式强行"调和"分歧。 真正需要权衡解读的冲突(LLM
  才擅长的活儿),留到深入探究和 adversarial/judge
  去做——那里能讲道理,而不是一个写死的加权和。席位层只做两件确定性的事:踩红线否决 + 矛盾打标。
