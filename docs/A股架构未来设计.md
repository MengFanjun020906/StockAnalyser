Stage6：信号质量校准模块6.1MFE/MAE框架
核心逻辑:每个信号发出后,跟踪其后续表现--MFE(Maximum Favorable Excursion,最大有利偏移)和MAE (Maximum Adverse Excursion,最大不利偏移)。
A股公式（只做多）：
MFE=（窗口内最高价-信号发出价）/信号发出价×100% MAE=（信号发出价-窗口内最低价）/信号发出价×100% A股时间窗口：窗口
用途1个交易日
短线验证3个交易日
中线验证5个交易日
波段验证
命中阈值：MFE>1%算命中（A股日线有意义波动通常>1%）。模块6.2置信度校准曲线
核心逻辑：将历史信号按置信度分桶（如60-70，70-80，80-90，90-100），统计每桶的实际命中率，与预期命中率对比。如果系统性偏高或偏低，对未来信号的置信度做校正。
A股适配：方法完全通用。A股可能出现牛市中高置信度信号实际命中率超预期、熊市中系统性偏高的模式。模块6.3信任分(Trust Score)

核心逻辑：EV=命中率×平均MFE-（1-命中率）×平均MAE。EV>0的信号源才值得跟随。
Stage7：风控与仓位输出模块7.1仓位算法
核心逻辑：风险定额模型——每笔交易的最大亏损不超过总资产的固定比例。 A股公式：
每笔最大风险金额=总资产×单笔风险比例（如1-2%）
每股风险=max（|买入价-止损价|，买入价×隔夜跳空风险系数）买入数量=min（最大风险金额/每股风险，可用资金/买入价）
I A股特殊点：
·无杠杆（A股现货不加杠杆）
·隔夜跳空风险系数：用历史低开幅度的95分位数（A股通常2-3%），因为T+1下止损只能次日开盘执行

跨阶段基础设施
以下模块不属于某个具体 Stage，但贯穿整条链路。基础设施A：统一LLM执行容器
核心概念：所有需要LLM判断的环节（数据语义过滤、技术分析、辩论、共识、复盘）由统一的调度运行时执行，而非每个阶段独立部署一个Agent。
设计要点：
·定时任务+事件触发的一次性任务共存于同一调度器
脚本预执行+LLM纯分析分离：数据拉取用确定性脚本（不依赖LLM），脚本输出注入LLM prompt；LLM只做分析和结构化输出
·支持并行调度，避免慢任务阻塞快任务基础设施B：事件驱动触发通道
核心概念：除了定时调度外，还有一条事件驱动的补充通道——外部事件（政策公告、异常资金流）可以立即触发一次分析，不用等下一个定时窗口。
设计要点：
·事件去重：相同事件短时间内（如30分钟）不重复触发
·目标限速：同一个分析任务不被事件洪流打爆
闭环追溯：最终信号可以追溯到是由哪个事件触发的
A股优势：A股事件驱动性比加密市场更强——降准降息、财报、北向资金异动等事件对股价的即时冲击远大于加密市场。
基础设施C：结构化输出协议
核心概念：Agent的输出不是自由文本，而是带结构化标记的多通道输出。后端/前端通过解析标记来路由不同类型的产出。必要的输出通道：

Hermes Agent框架（贯穿全链路的核心运行时）
Hermes Agent 是整套系统的"大脑底座"---Stage 1-7中所有需要LLM 参与的环节,都由Hermes Agent 统一调度和执行。它不是某个阶段的组件，而是驱动所有阶段运转的引擎。
Hermes是什么
Hermes Agent 是一个开源的LLM Agent框架（OpenAl兼容接口），本系统在其基础上做了大量扩展。它提供三个核心能
能力
说明Gateway(HTTP/WebSocket服务)
对外暴露OpenAl兼容的chat API，供前端用户交互式对话Cron 调度器
定时执行分析任务（如每5分钟跑一次技术分析、每小时跑一次宏观监控）
Skill系统
可插拔的技能模块，每个skill有独立的SKILL.md定义文件，Agent按需加载
Hermes在每个 Stage 中做什么

Stage 2环境感知

Hermes的作用：LLM读取技术面脚本产出，生成缠论/SMC的结构解读
