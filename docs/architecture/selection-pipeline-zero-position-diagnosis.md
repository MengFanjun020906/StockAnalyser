# 选股流程“0 仓”诊断：卡在哪一层

> **一句话结论：这 43 次运行的 0 仓，主要不是“当天确实没好机会”，而是当前输入与规则组合把“开仓”这件事几乎堵死了。** 最硬的一条是：**43 次运行全部没有账户现金数据**（`account_id` 为空，账户表 0 行，`available_cash` 为 `null`），而组合层提示词明确规定“账户摘要为空或可用现金缺失时，`portfolio_action` 不得为 `open`”。在这条规则下，无论候选多好，系统都只能输出 `wait` / `conditional_open`，`recommended_position_count` 必然为 0。
>
> 其次是深度分析层：131 条深度结论里 **129 条不是 `open`**（wait 109、monitor 17、reject 3），只有 1 条 `open`、1 条 `conditional_open`；其中 67 条（51%）命中“6 个核心维度里 2 个以上缺失/工具失败/未知则不得 open”的硬规则。唯一一条 `open`（600519，2026-05-31）又被 `risk_off` 大盘硬约束降级为 `wait`。
>
> 因此本次诊断的判断是：**当前配置下 0 仓是结构性、可预期的结果；它不能用来证明“策略没有 alpha”，也不能用来证明“当天没有机会”。** 真正的机会判断被前置的账户缺失、市场状态和证据缺口挡住了，尚未真正发生。

## 1. 给不看代码的人：先看这张漏斗

### 1.1 43 次运行的漏斗

| 层级 | 进入下一层的数量 | 说明 |
| --- | --- | --- |
| 有候选产物的委员会运行 | 44 次 | 62 次带候选阶段产物的运行中，18 次候选为空，44 次非空 |
| 候选股票 | 257 只（44 次） | 每次 1~20 只，常见 3~8 只；候选并不缺 |
| 通过初筛进入“深挖/观察/淘汰”分类 | 232 只 | 深挖 34、观察 107、淘汰 91；另有 25 只候选没有进入初筛短名单 |
| 实际做了深度分析 | 131 只 | 观察名单也会被拉进深挖；31/43 次有组合产物的运行，“深挖名单”其实是空的 |
| 深度结论为“可以开仓（open）” | **1 只** | 另 1 只 `conditional_open`；其余 129 只 wait/monitor/reject |
| 组合计划 | 127 条 | wait 108、monitor 15、reject 4；其中 106 条是“条件触发”模式 |
| 组合计划里首仓比例 > 0 | 13 条 | 比例只有 0.2%~5%，且动作全部是 `wait` |
| 计为“建议持仓” | **0 条** | 计数只认动作是 open/buy/add 且仓位 > 0 |

一句话：**候选有、观察名单有、条件计划也有，但没有一条被定义为“现在就买”。**

### 1.2 为什么“条件计划”不算持仓

系统把“等回踩再买”记录为 `action=wait` + `execution_mode=conditional_open`，首仓比例可以写 0.5%、2%、5% 作为“触发后的参考仓位”。但 `recommended_position_count` 的统计口径只数 `action` 属于 `open/buy/add/increase` 且仓位大于 0 的计划，所以 **106 条条件计划全部计为 0**。

这不是数据错误，而是口径选择：**“建议持仓数”只表示“无条件立即开仓的数量”，不表示“有多少只值得等”。** 对外只读这个数字，会误以为系统什么都没选出来。

### 1.3 判断：正常结果，还是几乎不可能？

| 判断 | 证据 |
| --- | --- |
| **几乎不可能开仓（主因）** | 43/43 次运行没有可用现金；提示词禁止在现金缺失时 open |
| **几乎不可能开仓（次因）** | 42/43 次运行没有任何一条深度结论为 open；唯一 open 被大盘风险状态强制降级 |
| **几乎不可能开仓（放大因素）** | 26/43 次运行处于 `risk_off` / `panic` / 高风险状态，系统硬性把 open 改成 wait、总仓位改成 0 |
| **确有“当天不便宜”的成分** | 深度分析普遍提到超买、追高、高波动派发；即使没有硬约束，模型也倾向 wait |
| **不能下的结论** | 不能据此说“选股没有 alpha”；因为真正的开仓判断从未发生 |

结论用一句话说：**现在的 0 仓是“制度性观察模式”的产物，不是对机会质量的最终裁决。**

## 3. 逐层证据

### 3.1 候选层：候选数量不是瓶颈

| 指标 | 实测 |
| --- | --- |
| 有候选的运行 | 44 次 |
| 候选总数 | 257 只 |
| 单次候选数 | 中位数 5 只，常见 3~8 只；两次旧格式各 20 只；两次单股测试各 1 只 |
| 候选来源 | 全部来自同日 seed pool；候选是 seed pool 的子集 |
| 席位立场 | `support` 44 只（17.1%）、`watch` 173 只（67.3%）、无立场 40 只（旧格式） |
| 候选置信度 | 217 只有数值，中位数 0.75，范围 0.2~1.0 |

**判断：不缺口。** 典型运行有 3~8 只候选，其中 1~6 只带 `support`。例如 2026-05-31 21:20 那次有 8 只候选、6 只 `support`，仍然 0 仓（见 §4 样本 B）。

### 3.2 席位/评分层：没有“超过建仓门槛”的候选，但门槛本身也不是主因

**（1）席位层没有数值分数。** 候选只记录 `stance`（support/watch）、`stance_by_desk`、`confidence`，不记录 0~100 的“席位得分”。所谓“排序”主要由立场和置信度决定，真正的买入判断被推迟到深度分析和组合层。

**（2）初筛分数分布：**

| 初筛结论 | 数量 | 分数范围 | 中位数 |
| --- | --- | --- | --- |
| 深挖 `deep_dive` | 34 | 60~83 | 60 |
| 观察 `monitor` | 107 | 34~78 | 55 |
| 淘汰 `reject` | 91 | 20~40 | 34 |
| 全部 | 232 | 20~83 | 46 |

- 只有 5 只达到 75 分，最高 83 分，**没有任何一只达到 85 或 88**。
- 代码里确实存在两个数值门槛：`AGENT_STRONG_WATCH_SCORE_MIN=85`、`AGENT_CONDITIONAL_ENTRY_SCORE_MIN=88`，用于在没有显式执行模式时判断“强观察/条件入场”。
- 但当前 106 条条件计划都自带 `execution_mode=conditional_open`，所以这两个门槛**没有实际参与本次 0 仓判定**；它们是一个“潜在死门槛”：一旦模型不返回执行模式，分数最高 83 也永远升不到条件入场。
- 组合计划里 `candidate_score` 字段基本为空（127 条计划中 0 条带数值），因此这条门槛路径在当前 trace 里无法被验证。

**判断：评分层不是 0 仓的直接原因，但“85/88 门槛高于实际分数上限”是一个需要单独记录的隐患。**

### 3.3 深度分析层：这是第一道真正把 open 挡住的闸门

131 条深度结论的动作分布：

| 动作 | 条数 | 占比 |
| --- | --- | --- |
| `wait` | 109 | 83.2% |
| `monitor` | 17 | 13.0% |
| `reject` | 3 | 2.3% |
| `open` | 1 | 0.8% |
| `conditional_open` | 1 | 0.8% |

**规则性原因：** 深度分析提示词第 8 条明确要求“6 个核心维度中有 2 个以上为 missing / tool_failed / unknown 时，`action_bias` 不得为 open”。实测：

- **67/131 条（51.1%）命中“2 个及以上维度缺失/失败/未知”**，按规则不能 open。
- 维度缺失集中在：消息面 `missing` 66 条、`unknown` 12 条、`tool_failed` 3 条；板块/市场 `missing` 47 条、`tool_failed` 16 条、`unknown` 2 条；基本面 `missing` 23 条。
- 124/131 条的 `main_missing_evidence` 非空。
- **止损位不是原因**：131 条深度结论全部给出了止损位，没有一条因“给不出止损”被卡。

剩下 64 条没有命中“2 维缺失”硬规则，仍然选择 wait。主要理由集中在：

- 短期超买/乖离过大/获利盘拥挤（“追高性价比不足”）；
- 市场处于高波动派发相位，要求等待回踩确认；
- 价格高于理想入场区或 `no_chase_line`；
- 账户适配度偏弱（偏长期、回撤控制严格）。

**判断：深度分析层本身是强保守偏好；即使没有账户和 regime 约束，它也会把绝大多数候选留在 wait。**

### 3.4 组合计划层：仓位怎么算，为什么是 0

**（1）回退路径（fallback）的算法最直白：**

- `action=open` → 首仓 = `min(10%, max_single_position_pct)`；
- `action=wait` → 首仓 = 0；
- 其它 → 首仓 = 0；
- 没有“综合分低于 X 就 0 仓”的评分规则。

**（2）模型路径的规则：**

- 单票不超过 `max_single_position_pct`，总仓位不超过 `max_total_equity_exposure_pct`；
- 首仓必须保守；
- **账户摘要为空或可用现金缺失时，`portfolio_action` 不得为 open**；
- `risk_off` / `panic` 时，`portfolio_action` 必须为 wait 或 reject；
- 所有标的都是 plain_wait/reject 时，`recommended_position_count` 必须为 0。

**（3）本次 43 次运行的计划分布：**

| 项目 | 实测 |
| --- | --- |
| 计划条数 | 127 |
| 动作 | wait 108、monitor 15、reject 4；**open 0 条** |
| 执行模式 | conditional_open 106、plain_wait 16、reject 3、strong_watch 2 |
| 首仓比例 > 0 | 13 条，取值 0.2%、0.3%、0.5%、1%、2%、5% |
| 单次总仓位最高 | 8.0%（2026-08-03），但被大盘硬约束覆盖为 0 |

**（4）仓位上限/止损参数不是原因：**

- 42/43 次运行账户约束为：单票上限 20%、总仓位上限 80%、默认止损 8%；
- 这些上限远高于实际写出的 0.2%~5%，没有一条计划因为“超过上限”被压到 0；
- 止损位全部存在，也没有因此触发降级。

**判断：组合层没有“分数不够就 0 仓”的规则；0 仓来自“没有 open 动作”与“账户/市场硬约束”，不是仓位公式或止损参数。**

### 3.5 硬性前置条件：账户与大盘状态

**（1）账户现金：43/43 次运行缺失**

| 证据 | 实测 |
| --- | --- |
| `request.json.account_id` | 43 次全部为 `null` |
| `portfolio_accounts` 表 | 0 行 |
| 组合层 `account_constraints.available_cash` | 42 次为 `null`，1 次为 `0.0` |
| 组合层文字说明 | 26/43 次的 `core_reason` 或 `main_constraint` 明确提到“账户摘要为空/可用现金缺失/资金数据滞后”；其余 17 次虽未写进文字，`available_cash` 同样为 `null` |

这不是某几次运行忘了传，而是**整个样本期内账户上下文都没有接上**。在这条数据缺失被修复前，提示词规则会稳定地禁止 open。

**（2）大盘状态：32/43 次被约束，26 次是硬性归零**

| 类别 | 次数 | 系统行为 |
| --- | --- | --- |
| 限制性状态（`risk_off` / `panic` / 风险高或极高 / 极端波动且非上行） | 26 | 强制把所有 `open` 改成 `wait`，总仓位和持仓数强制为 0 |
| 仅高波动（elevated/high_vol，但不属于限制性） | 6 | 首仓压到 5% 或 15%，不强制归零 |
| 无市场约束 | 11 | 不因大盘归零；但仍因账户缺失和深度结论为 wait 而归零 |

26 次限制性运行中，有 3 次模型原本写出了 1.0%、1.2%、8.0% 的条件计划仓位，随后摘要总仓位被覆盖为 0、持仓数改为 0（计划条目仍保留原条件仓位，供次日触发参考）。唯一一条深度 `open`（600519，2026-05-31）也在这类运行里，被改成 `wait`、仓位 0。

**（3）Judge 层最后再确认一次 0**

`judge_sanity` 会用“动作是 open/buy/add/increase 且仓位 > 0”重新统计持仓数；如果为 0，就把组合动作强制写成 `wait`。因此即使上游摘要写了 open，最后也会被纠正为 0。本次 43 次运行全部命中这条重算，其中 2 次 Judge 明确把全部候选降为 `monitor`。

## 5. 回答“正常结果还是几乎不可能”

### 5.1 结论

**当前配置下，0 仓是“几乎不可能不出现”的结果，不能当作“确实没好机会”的判断。**

四条必要条件里，第一条就已经 100% 失败：

1. 有账户现金 → **43/43 失败**；
2. 大盘不处于限制性状态 → 26/43 失败；
3. 深度分析给出 open → 42/43 次运行失败；
4. 组合动作是 open 且仓位 > 0 → 127 条计划里 0 条。

只要第 1 条不满足，提示词就禁止 open；所以“机会好不好”根本没有进入被检验的环节。

### 5.2 但也不能走另一个极端

样本期确实覆盖了较多 `risk_off` / 高波动 / 派发相位（2026-05 至 08 月、11 月），深度分析里“超买、追高、等回踩”的理由是真实存在的。因此：

- **能说的**：在当前账户与市场状态下，系统按设计不会开仓；0 仓是可解释的、稳定的。
- **不能说的**：不能说“选股流程没有 alpha”，也不能说“这段时间没有机会”。这两件事都需要在“有账户现金 + 非限制性市场”的条件下重跑才能判断。

### 5.3 这不是“参数调坏了”

本次没有发现“止损太紧”“仓位上限太低”“总仓位上限太低”把结果压到 0 的证据：

- 单票 20%、总仓位 80%、止损 8% 的约束都远宽于实际计划；
- 0 仓发生在写仓位之前，而不是写完被上限压掉；
- 唯一一次“有仓位被压掉”是 8% → 0，触发者是 `risk_off/extreme` 的市场状态硬约束，不是仓位参数。
