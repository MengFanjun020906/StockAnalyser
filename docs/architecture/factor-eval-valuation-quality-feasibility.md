# factor_eval 评估：估值分位与质量因子可行性

> 结论先行：估值分位（行业分位）已实现 `kind=valuation_pe` 并在主窗口跑出正式判定，结果为 **`fail`**（IC/ICIR/单调性/多空/偏效应未全部达标，非样本不足）。
> 质量因子仍**不能产出正式判定**：本地只有当前快照，缺历史数据层与 `quality_*` 特征分支。
> 本文不接入选股排序；否决开关保持 `false`，本轮不涉及否决逻辑。

## 1. 评估器现状

- 入口：`src/backtest/factor_eval/evaluator.py::evaluate_factor`，CLI 为 `scripts/evaluate_factor.py`。
- 数据源：只读 Tushare 快照 `daily` / `adj_factor` / `daily_basic` / `index_daily`；不退化为其它数据源，缺基准直接判评估错误。
- 已实现因子类型：`momentum`、`reversal`、`rsi_reversal`、`valuation_pe`；其它 `kind` 在 `_feature_matrices` 直接 `raise ValueError`。
- 协议口径：非重叠 `horizon` 交易日、T+1 开盘入场、T+H 收盘退出、20bp 成本、A 股 `000985.CSI` 基准；涨跌停/停牌/ST/上市时长不足的样本标记不可执行。
- 判定阈值（`factors.yaml`）：`min_coverage_not_evaluable=0.60`、`min_coverage_pass=0.80`、`min_executability=0.80`、`min_mean_rank_ic=0.03`、`min_icir=0.30`、`min_ic_t=2.0`、`min_monotonicity=0.80`。
- 关键约束：`coverage < 0.60` → `not_evaluable`；`0.60 ≤ coverage < 0.80` → 最多只能 `fail`，**不可能 `pass`**。
- 估值类例外（2026-11-18）：`kind=valuation_pe` 的覆盖率分母为"有 PE 的可估值样本"，同时输出 `valuable_ratio`；`valuable_ratio < 0.50` 时最多 `not_evaluable`。其它 kind 仍用全样本口径。

参考基线：同协议下 `reversal_5d`（2022-01-01~2026-11-13）有 1,113,458 条观测、1,177 个决策日 / 236 个 cohort、`coverage=0.983`、`executability=0.997`、行业收益率未匹配率 4.1%。

## 2. 估值分位（daily_basic 的 PE/PB）

### 2.1 候选定义

1. **行业内分位（已实现，主口径）**：当日 PE 在所属 SW2021 L1 行业内的百分位，方向 `negative`（越低越好）。横截面计算，不需要历史回看；行业有效样本 <5 只时置缺失。
2. **自身历史分位（未实现，第二口径）**：个股 PE 在过去 N 个交易日自身分布中的百分位，方向 `negative`。需要因子级回看窗口；受缓存起点限制，见 §2.2。

`pe_ttm_low` 已从"PE 原始水平"改为"PE 行业内分位"，`kind=valuation_pe`、`version` 升至 `1.0.0`；方向仍为 `negative`，属于事前固定，未因结果调整。

### 2.2 数据是否够跑

本地 `data/factor_eval_cache/basic_*.csv` 已有完整的 `daily_basic` 日快照：

| 指标 | 实测 |
| --- | --- |
| 覆盖区间 | 2021-10-13 ~ 2026-11-17 |
| 交易日数 | 1,237 |
| 每日股票数 | 约 4,488（2021）→ 5,573（2026） |
| PE>0 占比 | 均值 76.4%，最低 69.1%，P90 82.7% |
| PE>0 且 PB>0 占比 | 均值 76.3% |

字段包含 `pe_ttm`、`pb`，行业分位所需的 `industry_snapshot` 也在评估器里按 `in_date` 做点-in-time 匹配。**行业分位今天就能算，不需要额外取数。**

自身历史分位受缓存起点限制：

| 回看窗口 | 2022-01-01 起可评估所需历史 | 缺口与补数 |
| --- | --- | --- |
| 1 年（252 日） | 2021-01 起 | 约 200 个交易日缺口，约 200 次 `daily_basic` 调用 |
| 3 年（756 日） | 2019-01 起 | 约 700 个交易日缺口，约 700 次调用、约 0.6 GB CSV |
| 5 年（1,260 日） | 2017-01 起 | 约 1,200 个交易日缺口，约 1,200 次调用、约 1.1 GB CSV |

`daily_basic` 按 `trade_date` 一次返回全市场，所以调用量按"天"而不是"股票"计。若接受把评估起点后移（例如 1 年分位从 2022-10 开始、3 年分位从 2024-10 开始），则**零新增调用**。

### 2.3 覆盖率与协议口径调整

评估器使用**全市场**面板，不套用 `valuation_liquidity` 召回门槛。`PE<=0` 置为缺失（亏损股不能按"最便宜"排序），因此：

- 原口径 `coverage_full_universe = 有因子值观测 / 全样本`，实测 **73.47%**，低于 `min_coverage_pass=0.80`，按旧协议即使 IC 很好也只能 `fail`；
- 新口径 `coverage_valuable = 有因子值观测 / 有正 PE 的可估值样本`，实测 **96.29%**；
- `valuable_ratio = 可估值样本 / 全样本`，实测 **76.30%**，高于 50% 硬线。

口径调整理由与生效范围已写入评估协议 §4.3.1：亏损股无 PE 是经济事实，不应把"经济上不可估值"算作因子缺数据；该规则仅对 `kind=valuation_pe` 生效，其它 kind 仍用全样本 0.80 门槛。报告同时输出两种覆盖率，便于与历史结论对照。

`industry_unmatched_rate=0` 是在 eligible（已有因子值）样本上统计的，不代表行业数据无缺失；行业缺失或行业样本不足的股票拿不到分位、没有因子值，计入 valuable 内部约 3.7% 的 eligible 缺口。跨口径差额（73.47% vs 96.29%）完全来自 `valuable_ratio=76.30%`。

### 2.4 主窗口正式判定（2022-01-01 ~ 2026-11-17）

实现内容：

1. `_feature_matrices` 新增 `valuation_pe` 分支：按决策日 + SW2021 L1 行业分组，对 `PE>0` 做 `rank(pct=True)`，行业有效样本 <5 只置缺失；
2. `_build_observations` 分别统计 `valuable` 与 `eligible`，`_coverage_metrics` 同时给出两种覆盖率；
3. `_decide_verdict` 对估值类增加 `valuable_ratio < 0.50` 闸门（原因码 `low_valuable_ratio`），非估值类不受影响；
4. `factors.yaml` 升级 `pe_ttm_low` 至 `1.0.0`，方向 `negative` 事前固定。

主窗口结果：

| 指标 | 实测 |
| --- | --- |
| 样本 | 1,179 个决策日 / 236 个非重叠 cohort / 832,819 条可成交观测（全样本 1,135,685） |
| 覆盖率 | `coverage_valuable=96.29%`，`coverage_full_universe=73.47%`，`valuable_ratio=76.30%` |
| 可成交率 | 99.81% |
| Mean Rank IC | **0.0235**（门槛 0.03） |
| ICIR | **0.204**（门槛 0.30） |
| NW t | **3.11**（门槛 2.0，通过） |
| 正 IC 占比 | 57.4%（门槛 55%，通过） |
| MDE | 0.0210（≤0.03，功效足够） |
| 分组（Q1 最便宜） | -0.0016% / -0.0093% / +0.0032% / -0.0309% / -0.0672% |
| 单调性 | **0.70**（门槛 0.80；Q2<Q1、Q4<Q3 两处倒挂） |
| 多空 Q1−Q5 | +0.0656%，NW t 0.50，95% CI [-0.183%, +0.311%]（跨 0） |
| 偏效应 | partial IC 0.0160（NW t 2.92，门槛 0.02）；FM beta 0.000156（t 0.52） |
| 分状态 | 低波动状态为正（range +0.039 / bull +0.031 / bear +0.016），三个 high-vol 状态为负 |
| 判定 | **`fail`**，`promotion_eligible=false` |

结论：低 PE 行业内分位在全市场有**弱正向**排序能力（IC 0.0235，NW t 3.11），但幅度未达晋级门槛，分组不单调、多空价差 CI 跨 0、控制动量/市值/换手后偏 IC 低于 0.02，因此按协议判 `fail`，不接入排序。高波动状态下方向反转也说明它不是一个稳定的全市场因子。

按协议未做任何"换 horizon / 换分组数 / 换基准"的显著性尝试；以上即预注册口径的一次判定。

### 2.5 召回门槛（PE∈(0,35]）是否截断样本

`valuation_liquidity` 召回实测条件为 `0 < pe_ttm <= 35`、`0 < pb <= 4`、`turnover_rate >= 1`：

| 指标（2026-11-17 最新快照） | 数量 |
| --- | --- |
| 全市场行数 | 5,573 |
| PE>0 | 3,852 |
| PE∈(0,35] | 1,958 |
| PE∈(0,35] 且 PB∈(0,4] | 1,808（约全市场 32.4%） |

2022-01-01~2026-11-13 区间内，该门槛每日保留 1,215~2,707 只（均值占全市场 34.6%，区间 22.2%~51.2%）。

- `factor_eval` 的回放样本**没有被这个门槛截断**，它评估的是全市场因子；因此结论描述的是"全市场 PE 分位选股能力"，不能直接说成"召回池内有效"。
- 反过来，如果只在召回池内评估，样本只剩约 22%~51%（均值 34.6%），`coverage < 0.60` 会直接 `not_evaluable`（除非把 universe 重定义为召回池，那是另一个协议决定）。
- 更关键的是：召回门槛本身就条件在 PE 上（只收低 PE），PE 与未来收益的关系在截断样本里会变形，全市场结论不能外推到"PE<=35 子集"。要回答召回池问题，必须单独做带门槛的分层评估。

## 3. 质量因子（fina_indicator）

### 3.1 候选字段与数据源

- 目标字段：`roe`、`or_yoy`（营收同比）、`grossprofit_margin`；`fina_indicator` 还提供 `ann_date`（公告日）与 `end_date`（报告期）。
- `factor_eval` 数据层**没有** `fina_indicator` 读取，`_build_panel` 只合并 `daily` / `adj_factor` / `daily_basic` / `stock_basic` / `industry_snapshot`。
- 本地 `data/fundamental_candidates.db` 只是**当前快照**：606 个代码、3 个报告期（2026Q1~Q3）、每代码一行主键、字段含 `roe` / `revenue_yoy` / `gross_margin` / `ann_date`。没有历史序列，且每次刷新覆盖旧值，存在明显幸存者偏差，**不能用于回测**。

### 3.2 历史长度与调用量

`fina_indicator` 按股票查询且不传 `period` 时返回该股票全部历史季度（含 `ann_date`），因此：

| 方式 | 覆盖 | 调用量（全市场约 5,500 只） | 备注 |
| --- | --- | --- | --- |
| 逐股票 `fina_indicator(ts_code=...)` | 每只股票完整季度史（通常 10 年以上） | 约 5,500 次；按 200 次/分钟约 28 分钟 | 受积分/频率限制，适合离线一次性落地 |
| `fina_indicator_vip(period=...)` 按报告期全市场 | 每次一个报告期 | 约 4 次/年 × 年数 × 分页（约 40~90 次） | 仅在有 VIP 权限时可用，当前仓库未验证该权限 |

本地缓存体积很小（约 11 万行/5 年，几十 MB），不是瓶颈；瓶颈是首次取数与频率限制。

### 3.3 点时对齐（避免前视）

- 必须按 `ann_date` 而不是 `end_date` 对齐：T 日只能看到 `ann_date <= T` 的最新一期财报；`end_date` 到 `ann_date` 之间通常有 1~4 个月空窗。
- 建议在公告日之间前向填充（forward fill），并在超过一个报告期未更新时把因子置为缺失，避免用过期财报。
- 残余风险：Tushare 返回的是**最新修订值**，没有历史 vintage；后续财报重述会带来不可消除的前视偏差。文档与评估结论里必须标注，不能用"已规避前视"表述。

### 3.4 覆盖率与判定能力

- 回填历史后，日频覆盖率主要取决于"上市满 1 年 + 已有至少一期财报"，预计 85%~95%，高于 PE 分位，**有机会达到 `min_coverage_pass=0.80`**。
- 但质量因子行业差异大（银行/地产 ROE 与毛利率不可比），建议同时看行业分位版本或行业中性化，否则 primary IC 容易被行业结构主导；评估器的 partial IC 已控制 `industry_return_5d`，可作为辅助证据。
- **当前不能给出 `pass` / `fail` / `not_evaluable`**：因子未登记、数据层无 `fina_indicator`、特征层无 `quality_*` 分支。今天直接跑只会在 registry 查因子时报错，不存在"评估器判 not_evaluable"的路径。

## 4. 汇总

| 因子 | 数据够跑？ | 可覆盖时长 | 调用量 | 现有协议能否给判定 |
| --- | --- | --- | --- | --- |
| PE 行业内分位（`pe_ttm_low`） | 是（本地缓存完整） | 2022-01 ~ 2026-11 | 0（复用缓存） | **能：已判 `fail`**（IC 0.0235、ICIR 0.204、单调性 0.70、多空 CI 跨 0） |
| PE 自身历史分位 | 需补历史 | 1 年分位可从 2022-10 起；3 年从 2024-10 起；5 年需补到 2017 | 0~1,200 次 `daily_basic` | 否：逻辑未实现；扣掉回看缺口后覆盖率更低 |
| ROE / 营收增速 / 毛利率 | 否（只有 606 只当前快照） | 回填后理论可到 2015+ | 约 5,500 次逐股，或 40~90 次 VIP 按报告期 | 否：未登记、无数据层、无 `quality_*` 分支 |
| 召回池内（PE∈(0,35]）估值分位 | 数据够，但样本仅 22%~51%（均值 34.6%） | 同上 | 0 | 否：`coverage<0.60` 会 `not_evaluable`；需单独定义 universe |

## 5. 建议（不接排序）

1. **估值行业内分位到此为止**：已按 A 方案实现并跑出 `fail`，说明"全市场低 PE 行业内分位"只有弱正向排序能力，未达晋级门槛。不再为提升显著性更换 horizon、分组数或基准；如后续要再评估，必须先给出新的预注册口径并升因子版本。
2. **质量因子先做数据落地**：用逐股票 `fina_indicator` 或 VIP 按报告期回填，按 `ann_date` 建 PIT 表面，再实现 `quality_roe` 等 kind；否则任何"质量因子回测"都是当前快照的伪回测。
3. **召回池结论必须单独评估**：现有 `valuation_liquidity` 的 PE/PB 门槛会截断样本，全市场结论不能外推到召回池；如果业务只关心召回池，需要把 universe 显式改成召回池并接受 `not_evaluable` 风险。
4. 以上任一项落地前都不进入排序、不改入池门槛、不开启否决。
