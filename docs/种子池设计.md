# A股多 Agent 选股系统：种子池设计

本文档只讨论一个问题：

> 如何从全市场 4000+ 只股票中，筛出“此刻值得继续深度分析”的候选种子池。

它不讨论最终买卖动作，也不讨论下游深度分析细节。

---

## 1. 问题定义

### 1.1 核心矛盾

如果对全市场每只股票都直接做下游深度分析：

- 单只股票耗时高
- token 消耗高
- 很多股票此刻并没有新的决策机会

因此必须先做一个高效漏斗，把“值得现在花资源继续分析”的标的筛出来。

### 1.2 种子池的定位

种子池回答的是：

> 今天哪些股票有异常、有变化、值得继续看。

它**不**直接回答：

> 今天应该买什么。

所以要坚持三个边界：

- 入池 ≠ 看多
- 入池 ≠ 立即可买
- 入池只代表“值得继续花资源分析”

设计取向应是：

- 门槛偏低，宁可多看几只，也不要太早错杀
- 方向判断留给下游分析阶段
- 筛选阶段优先找“变化点”和“异常值”，不是找“长期好公司名单”

---

## 2. 整体漏斗结构

```text
全市场 4000+ 标的
    -> 第一层：硬排除
    -> 第二层：多维异常探测（确定性规则，无 LLM）
    -> 第三层：轻量评分（可选，仅在池子过大时启用）
```

目标规模建议：

| 阶段 | 目标规模 | 作用 |
| --- | --- | --- |
| 第一层：硬排除 | 4000+ -> ~3500 | 剔除不可交易/无意义标的 |
| 第二层：异常探测 | ~3500 -> 50-150 | 找到“此刻有变化”的股票 |
| 第三层：轻量评分 | 50-150 -> 10-30 | 资源有限时优先级收缩 |

---

## 3. 第一层：硬排除

这一层完全使用静态或确定性规则，目的是把“无意义标的”尽早排掉。

建议直接排除：

| 条件 | 原因 |
| --- | --- |
| ST / *ST / 退市整理期 | 风险不可控，不适合系统化交易 |
| 停牌中 | 无法交易 |
| 上市不满 60 个交易日 | 数据不足，技术分析不稳定 |
| 近 20 日日均成交额 < 1000 万 | 流动性不足 |
| 近 5 日出现连续一字涨停/跌停且无法正常成交 | 没有真实参与空间 |
| 科创板 / 北交所（可选） | 取决于账户权限与策略覆盖范围 |

执行节奏：

- 每日盘前跑一次即可
- 不需要 LLM

---

## 4. 第二层：多维异常探测

### 4.1 设计哲学

这里不是在找“好股票”，而是在找：

> 此刻有没有显著变化。

如果一只股票：

- 没有资金异常
- 没有技术突破/失衡
- 没有消息催化
- 没有板块联动

那它就不应该在此刻占用下游分析资源。

### 4.2 四类异常维度

---

### A. 资金面异常

| 信号 | 触发条件示例 | 说明 |
| --- | --- | --- |
| 北向资金突增 | 单日净买入 > 流通市值 0.3% | 外资突然关注 |
| 主力大单异动 | 当日大单净额 > 前 5 日均值 × 2 | 主力态度转变 |
| 融资余额突变 | 单日变动 > 前 20 日 2σ | 杠杆资金异动 |
| 龙虎榜出现 | 上榜且有知名机构/游资席位 | 市场关注度骤升 |
| 大宗交易异常 | 折价率 < 5% 或溢价成交 | 接盘方态度积极 |

---

### B. 技术面异常

| 信号 | 触发条件示例 | 说明 |
| --- | --- | --- |
| 价格突破 | 创 20/60/120 日新高或新低 | 趋势可能启动 |
| 放量突破 | 突破关键位且量能 > 5 日均量 × 1.5 | 有资金配合 |
| 均线信号 | MA20 / MA60 金叉或死叉 | 中期趋势转折 |
| 缩量蓄势 | 连续 5 日量能显著低于 20 日均量，且振幅收窄 | 变盘前兆 |
| 布林带变化 | 收口到近 60 日最窄后首次扩张 | 波动率突变 |
| 缺口 | 单日跳空缺口 > 1.5% | 情绪或信息驱动突变 |

---

### C. 消息面异常

| 信号 | 触发条件示例 | 说明 |
| --- | --- | --- |
| 业绩公告 | 业绩预告 / 快报 / 正式财报发布 | 基本面变化 |
| 重大事件 | 增持 / 回购 / 重组 / 定增 / 股权激励 | 公司级催化 |
| 行业政策 | 所属行业有高影响力政策出台 | 板块级催化 |
| 舆情突增 | 24h 讨论量 > 前 7 日均值 × 3 | 市场注意力聚集 |
| 研报集中 | 3 日内多家券商集中覆盖 | 机构关注提升 |
| 股东/高管动态 | 大额增减持、质押、解禁变化 | 内部人态度变化 |

---

### D. 关联 / 环境异常

| 信号 | 触发条件示例 | 说明 |
| --- | --- | --- |
| 板块领涨 | 所属板块涨幅 Top 5 | 板块共振 |
| 龙头效应 | 同概念龙头涨停而自身未涨停 | 补涨或联动机会 |
| 跨市场联动 | 港股 / 美股对标公司大涨 | 跨市场映射 |
| 期权信号 | 隐含波动率显著放大 | 市场预期变化 |
| 指数环境 | 大盘突破/跌破关键位时的 beta 弹性 | 指数驱动机会 |

---

## 5. 入池逻辑

### 5.1 入池规则

采用：

> OR 逻辑，而不是 AND 逻辑

即：

- 任一维度任一异常信号触发，即可入池

这样做的原因是避免在种子池阶段就引入片面性。

例如：

- 技术面没有明显信号
- 但资金面突然异动

这种标的仍然应该进入池子，交给下游继续验证。

### 5.2 入池后的排序原则

入池之后才考虑优先级。

建议排序分数由以下因素组成：

```text
priority_score =
    触发维度数权重
  + 单信号强度权重
  + 时效性加分
  + 流动性微调
```

各因素建议：

| 因素 | 逻辑 |
| --- | --- |
| 触发维度数 | 3 维共振 > 2 维共振 > 单维异常 |
| 单信号强度 | 偏离越大，分越高 |
| 时效性 | 最近 30 分钟 > 今日早盘 > 昨日盘后 |
| 流动性 | 日均成交额较大者略加分，便于执行 |

排序的意义不是“判断方向”，而是：

> 资源有限时，哪些股票应该优先进入下游分析。

---

## 6. 第三层：轻量评分（可选）

### 6.1 何时启用

只在第二层输出过大时启用。

建议阈值：

- 若种子池 ≤ 30 只：全部进入下游分析
- 若种子池 > 30 只：启用轻量门卫层

### 6.2 门卫层的职责

门卫层不判断：

- 看多还是看空
- 买不买

它只判断：

> 这个异常更像真信号，还是更像噪音。

### 6.3 门卫层输入

每只股票给一个轻量摘要即可，例如约 100-200 token：

- 触发了哪些异常
- 关键数值是什么
- 所属行业 / 市值 / 近几日走势背景

### 6.4 典型淘汰理由

| 理由 | 示例 |
| --- | --- |
| 放量但属于恐慌性抛售 | 放量跌停、多杀多 |
| 资金面只是小额噪音 | 北向净买入绝对额太小 |
| 消息已充分定价 | 利好 3 天前就出了 |
| 关联性弱 | 板块涨，但个股与主题弱相关 |
| 实际不可操作 | 一字板、无流动性 |

输出建议：

```json
{
  "worth_deep_analysis": true,
  "reason": "一句话",
  "priority_score": 0
}
```

## 7. 扫描节奏

### 7.1 盘前（08:30 - 09:15）

| 扫描内容 | 说明 |
| --- | --- |
| 隔夜消息面 | 公告、业绩、海外市场联动 |
| 集合竞价异常 | 09:15-09:25 挂单与量价异常 |

产出：

- 当日初始种子池

### 7.2 盘中（09:30 - 15:00）

| 频率 | 扫描内容 |
| --- | --- |
| 每 5 分钟 | 资金面异常 |
| 每 15 分钟 | 技术面异常 |

### 7.3 盘后（15:00 - 17:00）

| 扫描内容 | 说明 |
| --- | --- |
| 全量重算 | 用完整日线和盘后数据重新过全市场 |
| 龙虎榜 / 大宗 / 回购等盘后数据回补 | 为次日做准备 |

盘后全量重算的意义是：

- 兜底盘中扫描遗漏
- 弥补数据源延迟

## 8. 按市场状态动态调整

### 8.1 牛市 / 普涨

| 调整 | 原因 |
| --- | --- |
| 提高入池阈值 | 普涨时突破信号泛滥 |
| 提高资金权重 | 谁被资金持续推着走更重要 |
| 关注“未涨”标的 | 补涨逻辑更有意义 |

### 8.2 熊市 / 普跌

| 调整 | 原因 |
| --- | --- |
| 降低入池阈值 | 否则容易没有样本 |
| 提高消息权重 | 熊市更依赖事件驱动 |
| 增加逆势强势信号权重 | 大盘跌而个股不跌更有辨识度 |

### 8.3 震荡市

| 调整 | 原因 |
| --- | --- |
| 强调缩量蓄势 + 变盘突破 | 震荡后方向选择更重要 |
| 提高板块轮动权重 | 震荡市常见的是轮动而非全面趋势 |
| 缩短信号时效 | 信号有效窗口更短 |

### 8.4 市场状态判断

建议尽量用确定性指标，不用 LLM：

- 涨跌比连续 5 天明显偏多 -> 牛市模式
- 涨跌比连续 5 天明显偏空 -> 熊市模式
- 大盘中短期振幅持续收窄 -> 震荡模式
- 其余 -> 默认模式

---

## 9. 反片面性机制

这是种子池设计里最重要的部分。

### 9.1 入池用 OR，而不是 AND

- 单维异常即可入池
- 避免早期错杀

### 9.2 排序鼓励多维共振

- 多维度共振优先获得下游分析资源
- 这样下游分析样本天然更接近“值得认真看”的股票

### 9.3 各维度异常独立计算

- 资金面异常探测器不知道技术面结果
- 技术面异常探测器也不知道消息面结果

这样共振才是真正的独立证据，而不是同一个逻辑换皮重复打分。

### 9.4 门卫层只做噪音过滤，不做方向判断

方向判断必须留给下游分析阶段。

否则种子池阶段会过早引入主观偏见。

### 9.5 盘后全量重算兜底

即使盘中增量扫描遗漏了某只股票，盘后也能补回来。

---

## 10. 向下游传递什么

种子池传给下游的，不应该只是一个股票代码列表，而应该是结构化候选：

```text
SeedCandidate
  - symbol
  - name
  - trigger_signals
  - multi_dimension_count
  - priority_score
  - context_hint
  - freshness
```

其中 `trigger_signals` 至少应该包含：

- `dimension`
- `signal_type`
- `value`
- `threshold`
- `deviation`

## 11. 当前这份方案存在的问题

这部分是对原始思路的直接审查，不回避问题。

### 11.1 漏斗层次是对的，但“异常探测”和“共享种子池”是两套思路

文档主线是：

- 全市场先做异常探测
- 再形成种子池

但当前代码里 `candidate_experts_v2` 的实现不是这样。

当前实现更接近：

- 先从若干来源构造共享 seed pool
- 再由 expert 在 seed pool 上筛选

这两种体系不完全等价。

如果你要这份文档指导当前工程实现，建议明确：

- 它是**目标方案**
- 还是**当前实现的重构方向**

否则读的人会误以为当前代码已经具备“全市场异常探测层”。

### 11.2 “50-150 -> 10-30” 的规模设计合理，但对当前算力和接口成本要再约束

如果真的把 10-30 只都送进下游分析，而每只又要跑多组外部工具：

- 实时行情
- 趋势
- 价格结构
- 资金流
- 综合情报

总耗时会非常高。

目前更现实的建议是：

- 真实下游深挖上限先控制在 4-8
- 10-30 只更适合作为“候选观察池”，而不是全部深挖

### 11.3 “消息面异常”与“舆情突增”在工程上最不稳定

这些信号的理论价值高，但实际实现容易受：

- 搜索引擎稳定性
- API 额度
- 去重与时效过滤
- 新闻噪声

影响。

所以文档里最好单独写一句：

- 消息面信号默认视为高噪声维度
- 更适合作为入池补充维度，而不是单独决定优先级的主维度

### 11.4 当前“轻量评分门卫 Agent”定义仍偏抽象

门卫层现在说的是：

- 过滤噪音
- 不做方向判断

这个方向没问题，但还缺两个关键边界：

1. 它是否允许调用工具  
如果允许，就会重新变成一个小型专家层；如果不允许，就只能看摘要。

2. 它是规则引擎还是 LLM  
如果用 LLM，就要控制：
- 输入摘要格式
- 输出 schema
- 失败 fallback

否则它会成为新一层黑盒。

### 11.5 “关联 / 环境异常”建议拆成两类

原稿把：

- 板块联动
- 龙头效应
- 指数环境
- 跨市场联动
- 期权信号

都放在一维里，信息颗粒度过粗。

建议拆成：

- 板块 / 主题联动
- 宏观 / 指数 / 跨市场环境

这样下游更容易判断：

- 这是个股跟板块
- 还是市场环境导致的 beta 机会

### 11.6 缺少“低位来源 / 高位来源”双通道意识

这份种子池方案目前强调“异常”，但没有显式区分：

- 强势延续机会
- 低位启动机会

如果只做异常探测，很容易天然偏向：

- 涨停
- 热榜
- 放量突破

而忽略你更关注的“低位潜伏型机会”。

建议在文档里补一个明确原则：

- 种子池必须同时保留“高位强势异常”和“低位启动异常”两类来源

这样才能和你现在做的 `early_turn_expert` 路线对齐。

## 12. 建议怎么落到当前工程

如果要和当前 `candidate_experts_v2` 实现接轨，我建议改成下面这种映射：

| 文档层 | 当前工程建议 |
| --- | --- |
| 第一层：硬排除 | 保留在 `discover_watchlist_candidates` / committee seed 构建前 |
| 第二层：多维异常探测 | 拆成确定性 seed source，而不是一口气全市场 LLM |
| 第三层：轻量评分 | 可以先不做，或只在 seed > 阈值时启用 |

当前 `llm_expert_committee` 的落地状态：

- `local_price_volume` 已对本地 `stock_daily` 全市场先做硬排除，再按 OR 逻辑探测价量、突破、均线、缩量蓄势、缺口和低位转强等异常信号。
- 硬排除统计会进入 `hard_exclusion.local_universe`，包含全市场规模、扫描规模、排除规模和排除原因。
- 本地日线会推导轻量 `market_regime`，用于对牛市、熊市、震荡市下的 seed 优先分做确定性微调。
- 资金异动榜、龙虎榜、日度估值流动性已作为补充 seed source 接入；板块、消息、事件仍通过 `discover_watchlist_candidates(auto)` 补充，不作为本地确定性主链。
- LLM 门卫只在 seed 数量超过阈值时启用；小池子直接进入专家层，避免过早引入主观过滤。

对当前工程最有价值的，不是一次性实现整份目标方案，而是：

1. 把 seed source 做清楚
2. 保证各来源有可见性和配额
3. 让下游深挖上限与资源预算匹配

---

## 13. 总结

这份方案的优点：

- 漏斗分层思路是对的
- “异常探测而非方向判断”的定位是对的
- 反片面性原则是对的
- 可演化成强工程体系

这份方案当前最大的问题：

- 和当前工程实现路径并不完全同构
- 轻量评分层仍然偏抽象
- 对“低位潜力股”和“高位强势股”的双通道意识还不够明确
- 对真实 deep-dive 成本的约束还不够强

如果你要把它作为当前工程的直接设计稿，我建议下一步再补一版：

> “目标方案” 与 “当前落地方案” 对照版

这样大家在看文档时不会把未来设计误当成当前实现。
