# Agent 用户风险画像持久化开发、测试与验收规格

本文面向执行 AI，规定把 Trace 临时风险输入升级为跨页面、跨运行复用的用户级画像。首期只持久化投资偏好，不改账户管理能力；多市场全链路明确不在本任务范围。

## 现状与复用边界

`src/schemas/agent_context.py` 已有 `InvestorProfile`：风险偏好、周期、偏好市场、单票/总仓位上限、最大回撤、默认止损、融资/做空开关、备注。`api/v1/endpoints/agent.py` 当前从每次 Trace 请求构造画像；Web 表单位于 `AgentTracePage.tsx`。`PortfolioService` 管账户和持仓，画像不应复制账户余额/持仓，也不应替代账户模型。现有 `agent-user-context-plan.md` 第五阶段已明确正式设置入口尚未产品化。

## 产品与数据规则

- 当前认证是单实例管理员会话，没有 user ID/多租户身份模型。画像首期归属当前部署实例，单实例一份默认画像；读写沿用现有管理员认证开关，不要虚构用户 ID，也不要顺便实现多画像/账户画像矩阵。
- 只保存 schema 中的投资偏好字段及 `profile_id`、创建/更新时间、schema 版本。账户、持仓、价格、资产净值等动态事实仍由 PortfolioService 构造。
- 未设置画像时保留现有默认值语义，并在 context metadata 中标记来源为 `default`；已设置画像标记 `profile`。Trace 本次显式覆盖只作用于本次运行，不静默覆盖持久画像。
- 持久画像和单次覆盖的字段优先级固定为：本次明确输入 > 用户默认画像 > schema 默认值。页面应能看出本次运行覆盖了哪些字段。
- 不允许将画像备注当作系统指令或未经验证的事实；按普通用户文本处理并保留长度限制。风险参数接受 0-100 边界，枚举沿用 schema。

## 实现步骤

1. 检查现有管理员会话依赖、认证启用/关闭时的 API 约定和 SQLAlchemy/SQLite schema 初始化方式。认证开启时画像读写必须要求有效管理员会话；认证关闭时遵循项目既有本地单实例语义，不接受客户端传入归属 ID。
2. 新增 repository/service 和幂等迁移，读、创建/更新默认画像。删除/重置如提供，必须显式确认并回到默认值；不能因空 PATCH 清空整份画像。
3. 增加经认证的 GET/PUT（或仓库既有资源更新风格）画像 API。响应只回传该用户画像；校验非法枚举、越界数字、额外字段策略和备注长度；统一 401/403/422 行为。
4. 在 Agent Trace context 构造中加载默认画像，并叠加本次明确提交的字段。确保 SSE 与非流式接口共享同一构造逻辑，且不把 profile 写回历史 Trace 时丢失来源/快照。
5. 在现有 `/settings` 增加“Agent 风险画像”区块，不新建独立导航体系。加载、保存、恢复默认、校验失败、未登录状态完整；Agent Trace 初次加载画像并允许本次覆盖，新增“使用默认画像”恢复动作。
6. 补 API schema/类型、API spec 与中文设置文档。由于只新增中文模块文档，不强制创建整份英文对照；若修改英文指南再同步对应章节。

## 测试验证

后端：不同用户隔离；首次读取默认状态；创建和更新所有字段；部分更新不会覆盖未提供字段；无效枚举、边界外数值、超长备注被拒；未认证请求拒绝；Trace 未提供本次字段时使用持久值，单次字段覆盖持久值但不写回；SSE 与 run 返回一致 context；旧请求完全不带画像字段保持兼容。

Web：已有画像加载/保存/错误重试；保存成功后刷新仍显示持久值；Trace 从默认画像预填；单次修改不改变 Settings 默认值；恢复默认和表单边界验证。页面测试使用 API mock，覆盖 401/422。

执行阶段按实际测试文件运行画像/API/Trace 定向 pytest、`rtk python -m py_compile <changed_python_files>`、Web `rtk npm run lint`、`rtk npm run build`，最后 `rtk ./scripts/ci_gate.sh`。重点验证数据库隔离而不只测试 schema 校验。

## 验收条件

- 用户保存后可跨刷新和后续 Trace 复用。
- 在当前单实例认证模型下，认证开启时未登录请求不能读写画像；API 不接受客户端指定归属 ID。
- 单次 Trace 覆盖可用但不会反向污染默认画像。
- 账户/持仓仍来自现有 Portfolio 服务，画像不会生成虚假账户上下文。
- 不改账户 CRUD、不做多市场策略支持、不自动推断用户风险偏好。

## 交付与回滚

修改用户可见设置和 API 时更新 `docs/CHANGELOG.md`、API spec 和设置专题文档。若迁移或服务回滚，旧 Trace 临时参数路径继续工作；画像表数据保留，不做破坏性删除。交付报告注明认证/租户隔离验证结果及默认值兼容性。
