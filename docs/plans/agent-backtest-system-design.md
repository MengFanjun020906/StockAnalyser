# Agent 回测系统设计与执行规格

状态：P0-A/B/C 已实现（2026-11-08）；P3 历史 Agent 研究首版垂直切片已实现（显式标的池 / Sequoia 全市场本地覆盖自动候选、月度、选股→单股确认、LLM 预算/缓存）；P2 历史规则策略未实现。日期：2026-11-08。面向执行 AI；必须按阶段交付及验收，不得自行省略资金账本、数据质量和防前视约束。使用说明见 `docs/backtest/portfolio-backtest.md`。

## 1. 已确认的范围与优先级

用户已确认：同时设计已有 Agent 方案回放和历史日期重新选股，先实现前者；模拟完整资金账户（现金、仓位、费用、滑点）；日线做长期研究、5 分钟线做计划撮合；只做 A 股，不做账户管理扩展或实盘交易。回测系统是当前优先建设项，模拟盘托管应建立在验证通过的公共执行内核上。

本规格定义完整目标和首期可交付边界。与旧 `agent-entry-execution-backtest-plan.md` 的“无本金、不计费用、信号等权”不冲突：旧结果保留为单笔诊断，本系统新增资金受限的组合实验，不能将旧结果改名成组合回测。

首期不需要新增付费数据源或 LLM 调用。历史 Agent 重跑放在最后阶段，先解决 point-in-time 数据与工具隔离，不能用今天的数据重跑过去再宣称历史有效。

## 3. 三种实验模式

| mode | 输入 | 能回答什么 | 不能声称什么 |
| --- | --- | --- | --- |
| `recorded_plan_replay`（P0） | 当时实际生成的 Trace/结构化方案 | 历史已记录建议在指定资金和执行规则下的组合表现 | 全市场选股策略历史收益 |
| `historical_rule_strategy`（P2） | 版本化确定性策略 + 当时股票池/特征 | 历史逐时点生成信号的策略表现 | Agent 当年的真实决策表现 |
| `historical_agent_research`（P3） | as-of 工具环境 + 固定模型/Prompt + 历史数据 | 受控条件下重建决策的研究结果 | 完全排除模型参数记忆/训练知识泄漏 |

三者可共享行情、撮合、资金账本、指标和 UI，但必须独立标记样本来源和偏差；不混算主指标。每个对照策略独立运行同样初始资金，不共享现金或成交。

## 4. 架构和代码落点

建议最小边界（执行前查是否已有同职责实现）：`src/backtest/` 放 schemas、clock、data_view、plan_adapter、execution、ledger、metrics、runner；`src/repositories/backtest_run_repo.py` 保存实验；`src/services/backtest_run_service.py` 管任务/API；端点仍在 `api/v1/endpoints/`。业务代码不得放 vendor。若现有模块适合扩展，复用而非创建同义实现。

数据流固定为：创建不可变实验配置 -> 输入预检/覆盖清单 -> 固定输入快照 -> 逐事件推进逻辑时钟 -> 适配计划/信号 -> 风控与资金预留 -> 委托/成交 -> 现金与批次持仓记账 -> 收盘估值 -> 指标与审计结果。

纯执行内核不访问网络、不调用 LLM、不使用真实当前时间、不读取 Portfolio 真实账本。数据下载是独立任务；策略只通过 as-of DataView 读取数据。模拟盘以后复用 execution/ledger/risk policy，通过实时 clock/data adapter 接入；第一版不得顺手实现托管调度。

## 5. 实验配置与可复现身份

请求至少包含 `mode`、起止时间（Asia/Shanghai）、输入选择（Trace IDs/时间段或 strategy ID）、初始本金、CNY、空仓起始、单票/总仓位上限、费用策略版本、滑点 bps、成交量参与率、基准、撮合粒度与缺失策略、入场/退出规则版本、期末政策。首期只允许空仓开始，无杠杆/做空/外部出入金。

可提供可编辑参考值：本金 100000 元、单票 20%、总仓位 80%、最大成交量参与率 1%、滑点每边 5bps、年化无风险利率 0；这些是实验假设，不是投资建议或校准结果，不能成为隐藏常量。费用必须从版本化费率策略读取并在表单预览；不能因缺失费率静默当零。系统级新增环境配置同步 `.env.example` 和说明；每个实验参数不必做环境变量。

规范化配置、引擎版本/Git revision（含 dirty 标识）、策略/Prompt/模型版本、输入计划内容 hash、数据 manifest hash、规则/日历/公司行为版本一起构成 `experiment_fingerprint`。相同 fingerprint 可复用成功结果；重新运行生成 attempt，不覆盖旧结果。相同快照/版本/配置应产生相同订单与净值（忽略任务执行时间）。

## 6. 数据合同：时间、行情、公司行为

所有输入记录区分 `event_time`（事实发生）、`available_at`（当时可获得）、`ingested_at`（本地采集）。策略只能见 `available_at <= clock` 的记录；成交引擎可读取当前完整撮合 bar，但策略在 bar 收盘前不能读取该 bar high/low/close。日线指标在当日收盘完成后才可用。5 分钟 bar 的时间戳统一为区间结束，保存 session/时区，检查午休、交易日、重复、乱序和单位。

P0 的真实 Trace 方案以方案最终可用时间为下限，不以行情锚点日代替生成时间：周五数据周日生成的方案只能在周一开始；事后补生成的旧日期方案不得在补生成前成交。只有日期且无法证明可用时间的旧样本，保守设为该自然日结束后可用，并标明 `timestamp_inferred`；来源时间冲突/未知则排除并计入输入失败。

撮合使用不复权成交价及真实数量。指标可用截至时点可构造的调整序列；不得用含未来公司行为的今天前复权值生成过去信号。分红送转拆并股调整现金、持仓、成本及未完成订单；具体生效时点和税务假设记录为版本。缺公司行为数据且持仓跨除权日时，严格实验阻断/partial，不把价格跳变当亏损或盈利。基准同样声明价格/全收益口径，不能用个股总收益与价格指数混称超额。

snapshot manifest 至少包含标的/日期/粒度、provider、复权口径、单位、覆盖、缺口、校验和、抓取时间、规则快照。必须保留不可变数据副本或内容寻址文件；仅保存 hash 再读可变缓存不足以复现。大表快照可用本地 Parquet（已有依赖优先）/SQLite，存储路径从项目数据根解析，API 不允许任意本地路径读取。

预检区分休市、停牌、上市前、缺失行情，不能“有一根分钟线就算全天覆盖”。默认严格 5 分钟模式：缺关键撮合数据不得成交；提供显式 daily 降级实验，但生成新 fingerprint，逐日记录降级/歧义，结果标 `mixed_granularity`。不得跨缺口直接认为止损未触发。持仓缺估值时可携带上次价供临时展示，但标 stale，净值/风险指标不得标为完整可信。

## 7. 计划适配和输入选择

优先使用价格 repository 中结构化 artifact、对应 Trace account decision 与 Risk Gate；规范化为 `ReplayPlan`：source ID/revision/hash、symbol、available_at、valid_from/until、动作、场景、条件、订单类型、止损止盈/退出、目标仓位、证据/规则引用。只有机器可判定的条件可执行，LLM 自然语言计划不得猜测成自动成交。旧 best-effort 提取保留为诊断，`parse_failed/unsupported_condition` 进入排除清单，不能静默丢样本。

同一价格 artifact 可能关联多个 Trace，按 plan/revision 去重，不能按 Trace 数重复买入；不得事后选收益最好的 scenario。严格策略只选择当时 account decision 认可且闸门允许的场景，缺失选择为不可评估；中性场景对照另列。新的同标的计划只撤销尚未成交的旧入场委托；已有持仓默认继续原退出方案，不因“又推荐了”自动加仓/换止损。明确加仓/减仓需独立动作和资金/风险检查。

每个实验保存纳入/排除的全部输入、原因和数量。P0 样本有真实生成历史的选择偏差；UI 必须展示覆盖起止日及未覆盖日期，不解释成完整历史选股。

## 8. 事件顺序与资金竞争

所有标的共用单一逻辑时钟。每个时间点顺序：生效的公司行为/T+1 解锁 -> 已有委托撮合（卖出优先） -> 成交事务入账与释放预留 -> 公开完整 bar/策略计算 -> 接受新计划/风控/生成委托（最早下一 bar 成交） -> 收盘估值/记录。订单存在明确时间优先规则，不能按数据库无序遍历导致结果漂移。

多个同时间买入竞争现金时按已记录优先级（当时 rank，缺 rank 最后）、available_at、标准化 symbol、plan ID 稳定排序；不按未来收益重排。仓位目标解释为账户权益比例：下单时以最后已知估值计算目标数量，向市场合法单位取整，并受单票/总仓位/现金（含费用）限制。只给退出计划且账户空仓时标 `no_position`，不能虚构持仓。

待成交买单冻结最大应付金额和费用预算，撤销/过期释放；卖单冻结可卖数量。买单不得重复占用同一现金；市价委托需指定价格保护和预算上限。滑点后超预算缩量至合法单位，仍买不起则拒绝并记原因。A 股卖出资金当日可用于买入，但可提现和可交易现金分别记录；首期没有提现功能。

## 9. 撮合规则（首期必须逐条实现）

只覆盖有可验证历史规则的 A 股普通股票，按证券/日期读取 tick、买入单位、价格限制及 T+1；北交所/ST/新股不能套主板统一规则，缺规则标 unsupported/partial，不伪装全 A 股覆盖。不支持融资融券、ETF T+0、集合竞价精确队列和逐笔成交。

- bar 收盘确认的突破/技术条件，最早下一可交易 bar 执行；不得拿确认 bar 的最低价回填买入。
- 买入限价 L：若 bar open <= L，参考 open，否则 low <= L 才可参考 L；滑点后不能高于限价，超出则不成交。卖限价镜像处理。买入区间默认是“价格落在区间才接受”，open 跳空低于下沿不自动买入；若业务选择上沿限价，必须作为独立 policy 明示。
- 预先存在的 stop-market 卖单：open 跳空跌破 stop 按 open 扣滑点，不能按较好的 stop 价退出；bar 内触发按 stop 扣滑点。止盈采用预先存在限价单语义。
- 同一 bar 止损/止盈均可触发时使用预注册保守 stop-first，并记 ambiguous；不推测 OHLC 路径。新增买单与退出同 bar 无法排序时同样标歧义，且 T+1 禁止当日卖出新买数量。
- 停牌/零量不成交；一字涨停不模拟买入，一字跌停不模拟卖出；其他触板成交保留流动性假设标签，不宣称真实排队可成交。历史涨跌停以当日规则和参考价计算。
- 每 bar 可成交数量受 volume 单位标准化后的参与率限制，共享同标的容量预算；允许部分成交，剩余单保留/到期。OHLC 不能证明真实流动性，报告该假设。
- 佣金、最低佣金、过户费、印花税按生效日期/买卖方向计算；部分成交按委托/交易日汇总最低佣金并做费用补差事件，不能每个 5 分钟片段重复收最低佣金。所有内部金额用 Decimal/明确舍入，输出约定百分比单位。
- 有效期按交易日历计数，停牌不当休市；买入当日数量次交易日可卖。到期未成交记 expired；持仓止损遇 T+1/跌停保留退出待执行，不“强制假成交”。
- 期末默认撤未成交单，持仓按最后有效收盘价 mark-to-market，分别显示实现/未实现收益；不默认最后一日全部卖出。可选清算实验遵守可卖/停牌/流动性约束，未能清算仍保留持仓。

费用/滑点参考值不是现实成交保证。支持零滑点诊断及更高滑点压力测试，必须与主实验分开列示。

## 11. 指标、对照与归因

主指标按日终组合权益计算，不将单笔平均收益拼成净值：总收益、日收益序列、最大回撤及区间/恢复时间、年化收益、波动、Sharpe、基准收益/超额、现金比例、平均仓位、换手、费用/滑点拖累。年化交易日参数和 rf 写入配置；短于 252 交易日的年化标“短样本外推”，少于 20 个有效日收益不输出 Sharpe/年化波动。零波动、空成交、无亏损时指标用 null + 原因，禁止 infinity/NaN。

计算：日收益=E_t/E_(t-1)-1；总收益=E_end/E_start-1；回撤=E_t/历史最高权益-1；年化收益=(E_end/E_start)^(252/N)-1（N 为实际交易日收益数）；Sharpe=mean(r-rf_daily)/sample_std(r-rf_daily)*sqrt(252)。单位明确，pct 为百分数，不与 ratio 混用。

单笔诊断另列：信号纳入/解析失败/闸门阻断/资金不足/未触发/部分成交数量、成交率、已平仓胜率/盈亏比/期望、持有期、MFE/MAE、止损止盈/超时、未成交机会成本。分母明确，未平仓不算已实现胜率；分批退出按可追溯 FIFO 配对，成本/费用归属一致。组合最大回撤与单笔 MAE 分开展示。

基准首期可选沪深300价格指数，使用确定的指数 ID（不能以裸 000001 混用股票/指数）。严格同区间、日历、覆盖与口径，缺数据基准标 unavailable。对照至少包括现金、固定基准、严格原计划和 next-open 诊断；旧 ATR/突破策略保留为版本化独立实验，不能事后选最佳对照当主结果。next-open 若违背原 Risk Gate，只能标为非可执行研究对照，不能当托管建议。

归因按原始计划日期、来源/策略版本、Regime、执行模式聚合，展示样本量和时间覆盖。必须能分开定位“选股不好、没有触发、资金不足、成交受阻、费用吞噬、退出规则失效”，不能只给一个胜率。

## 12. 长任务、API 与 Web

沿用现有认证开关/管理员会话，不新增用户体系。建议新增 `/api/v1/backtest/runs` 资源（具体挂载前核对 router）：POST 创建并返回 202/run_id；GET 列表；GET /{id} 状态与摘要；GET /{id}/equity、/orders、/fills、/inputs、/diagnostics 分页；POST /{id}/cancel。数据预检/同步单独资源返回 job ID，纯回测不会静默下载。请求拒绝路径注入、超大日期范围/无限任务参数，错误码稳定。

状态：queued -> validating -> running -> succeeded / partial / failed / cancelled；progress 表示逻辑时钟进度；partial 的结果只能研究展示，不伪装完整成功。首期持久队列加单 worker 足够，不引入 Redis/Celery；任务声明/租约及事件提交幂等。服务重启发现中断 attempt 标 interrupted 后可显式从冻结输入重跑；首期不宣称断点续算。取消在安全事件边界生效，保留诊断，不发布最终成功指标。

Web 回测页包含：实验列表/新建、输入范围与预检、资金/费率/执行假设、运行进度和取消、净值/基准/回撤、订单/成交/持仓明细、输入排除原因/行情覆盖/歧义、同口径对比。计划点击可回到 Trace/价格 artifact，图上每个成交可追溯至订单和 bar。创建前预览精确配置；没有完整数据明确阻断或让用户选择新降级实验，不静默 fallback。结果支持导出 config/manifest/metrics JSON 和 ledger/fills CSV，导出不得含密钥。

## 13. 历史重新选股与 Agent 研究设计

P2 先建确定性策略适配器：`generate_signals(as_of, data_view, portfolio_snapshot, params) -> signals`，禁止直接调用当前行情/provider singleton。每个交易日先用前一收盘可见数据生成信号，再由统一内核执行。股票池按当时上市/退市/ST/板块身份、指数成分生成，不使用今天存活股票名单过滤过去；缺 point-in-time 股票池只能标 survivor_bias research，不能发正式策略收益结论。财报按公告可用时间而非报告期，修订保留版本。

P3 让 Agent 所有工具经历史 DataView/recorded tool adapter；新闻按发布/已知修订时间过滤，历史搜索不许向实时搜索补证；Regime、基本面、候选发现、缓存、图谱也必须隔离截止时间。任一关键工具不能提供 as-of 数据时 fail closed 或输出研究缺口，不用今天返回值“凑齐”。

Agent 实验固定 Prompt/模型可用版本、参数、工具响应快照、随机 seed（若支持）、调用成本/预算和输出；LLM 不能保证位级可复现，因此区分“重放已记录 Agent 输出”（可确定重放）和“重新调用模型”（新 attempt，可能不同）。新模型可能知道历史后续事件，即使工具隔离也无法证明无泄漏；结果必须标 `model_knowledge_leakage_risk`，可信验证以从今天起前向记录方案/模拟盘为准。

训练/调参/验证按时间切分，walk-forward 每折只用过去样本，跨窗口持仓/标签 purge 并 embargo 至少最大标签/持有窗口，最终留出段不得反复调参。记录所有参数试验数量和失败项，不能只展示最好组合。回测评估权重只能由当时已成熟样本计算，不能把全期评估权重回写到过去选股。首期不自动反哺生产 Prompt/权重。

## 14. 分阶段任务与硬验收门槛

| 阶段 | 可交付内容 | 必须通过的门槛 |
| --- | --- | --- |
| P0-A 规范/数据 | schemas、计划适配、时间规则、manifest、预检、不可变输入 | 真实 Trace 可列出纳入/排除；历史分钟缺口和规则缺失可解释；没有网络副作用 |
| P0-B 内核/账本 | 单 clock、多标的、T+1、订单/部分成交、费用、净值 | 手算金标准通过、并发资金不超支、无未来成交、重放结果一致 |
| P0-C 产品 | 异步任务/API/Web、主/对照实验、导出 | 重启中断/取消可见；完整端到端；数据 partial 不冒充成功 |
| P1 稳健性/共用 | 压力测试、旧诊断差异报告、模拟盘公共内核接口 | 差异均有解释；新旧 API 兼容；纯内核可注入实时/历史 clock |
| P2 历史规则策略 | PIT 股票池/特征、适配器、walk-forward | future mutation 不改变过去信号；偏差/调参边界可审计 |
| P3 历史 Agent | 历史工具沙箱、调用缓存/成本、模型泄漏标签 | 实时工具不可达，所有输入可追溯，明确研究结论边界 |

先完成 P0-C 才可声称“已有方案的组合回测系统可用”；P2/P3 作为明确待实施阶段保留，不假装首期全部完成。P0 不等待画像持久化：用实验/计划快照参数；不修改真实账户或自动启用托管。

## 15. 测试矩阵与手算金标准

测试要验证账本和结果，不能只断言 mock 被调用。固定合成行情/日历/规则，无外网依赖。必须至少覆盖：

1. **资金竞争**：资金10000、零费用/滑点，两个同时到期的10000买单，策略排序固定；第一只全成后第二只资金不足，现金不负，换输入顺序结果不变。
2. **费用手算**：100股10元买入，100股11元卖出；每笔最低佣金5元、仅卖出印花税0.05%、其他费率0；买入现金减少1005，卖出增加1094.45，净利润89.45，资金10000期末10089.45。部分成交拆到多个 bar 仍按声明费用政策核对。
3. **T+1**：当天买入后跌破止损，不卖新买数量；次交易日跳空8元，按8元减滑点而非9元止损价成交。老仓可卖、新仓不可卖独立核对。
4. **防前视**：变更未来 bar/news/财报/候选权重，不改变变更前的信号与委托；收盘确认不得在该 bar 成交；周日生成周五锚点方案不得周五成交。
5. **成交约束**：涨跌停、停牌、量能、限价保护、跳空、同 bar 双触发、部分成交/取消释放预留、合法数量取整和费后资金不足。
6. **数据/公司行为**：乱序重复、午休、单位、缺5分钟段、日线降级新指纹、跨除权现金/数量守恒、缺规则阻断、数据重下载不改旧快照。
7. **指标**：手算净值100->110->99，对应收益10%/-10%、回撤-10%、总收益-1%；空成交/零方差/短样本返回明确 null；已平仓胜率不包含未平仓。
8. **持久化任务**：事务故障无半笔成交、重试幂等、不同 run 隔离、服务中断与取消、冻结输入重跑一致、API非法参数/认证/分页/导出。
9. **Web/E2E**：预检失败/下载/配置/任务/结果、partial及错误态、净值与成交联动；至少一条固定fixture的“创建->完成->查看成交->导出”主流程。

执行时新增 `tests/test_backtest_execution.py`、`test_backtest_ledger.py`、`test_backtest_data_view.py`、`test_backtest_runs_api.py` 等与实际落点对应的测试；回归现有 `test_backtest_engine.py`、`test_backtest_service.py`、`test_backtest_summary.py`、`test_agent_entry_execution_backtest_service.py`、`test_deterministic_price_plan_backtest.py`。先定向 pytest，再 `rtk ./scripts/ci_gate.sh`、改动 Python 的 py_compile；Web 在 `apps/dsa-web` 执行 `rtk npm ci`、定向 vitest、`rtk npm run lint`、`rtk npm run build`、固定数据 Playwright。网络 provider smoke 单独记录，不作为离线单测依赖。

## 16. 最终交付证据、风险与回滚

执行 AI 交付必须附：一个固定 fixture 的 config/manifest、完整 ledger/fills/equity/metrics、手算对账、重复运行一致性结果、旧新口径差异、数据覆盖/排除列表、实际测试命令与结果；未完成的 P2/P3 标明，不得用页面截图代替账本验证。不得声称收益保证或把缺失样本算零收益掩盖错误。

实现时同步 API spec、模块使用文档、必要配置示例与扁平 CHANGELOG。迁移只追加新实验表/索引，旧 backtest/JSONL/Trace/Portfolio 不破坏；回滚关闭新任务入口/worker，保留数据与旧诊断，不能删除实验快照。中文新增设计无对应英文设计，暂不新增英文全文；未来若修改双语使用指南需同步对应功能说明。
