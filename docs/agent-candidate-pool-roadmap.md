# Agent 候选池策略缺口与建设路线

> 目标：把 `watchlist_scan` 的候选池做成真正可靠的 L1 入口。后续深度分析、反方审查和 Judge 裁决都依赖候选池质量；如果 L1 只召回了偏消息面的弱候选，后面再多专家也只能围绕弱候选做验证。

## 1. 当前可用能力

### 1.1 AlphaSift 策略多因子候选

当前已接入 8 个 YAML 策略：

| 策略 | 主要用途 | 当前定位 |
| --- | --- | --- |
| `balanced_alpha` | 估值、流动性、动量、稳定性均衡筛选 | 通用候选 |
| `capital_heat` | 量价活跃、换手和成交额放大的短线候选 | 资金热度代理 |
| `dual_low` | 低 PE、低 PB 的稳健价值候选 | 防守/价值 |
| `momentum_quality` | 趋势确认 + 基本面质量约束 | 中线趋势 |
| `oversold_reversal` | 可控下跌后的修复观察 | 反转修复 |
| `quality_value` | 估值合理、波动不过热的大市值稳健股 | 价值质量 |
| `shrink_pullback` | 上升趋势里的缩量回踩 | 趋势回踩 |
| `volume_breakout` | 放量突破关键阻力 | 趋势突破 |

优势：

- YAML 可配置，适合快速扩展和调参。
- 比 LLM 直接选股更稳定，可全市场硬筛。
- 可以作为候选池主干来源之一。

不足：

- 资金字段多为成交额、换手率、量比代理，还不是真实主力资金流。
- 基本面主要依赖估值和市值，缺少成长、盈利质量、现金流等高质量字段。
- 策略之间有较多趋势/动量重叠，风格分散度仍不足。

### 1.2 Sequoia 技术形态候选

当前已接入 6 个技术形态策略：

| 策略 | 主要用途 | 当前定位 |
| --- | --- | --- |
| `ma_volume` | 均线金叉 + 放量 | 趋势启动 |
| `turtle_trade` | 海龟突破 | 突破动量 |
| `high_tight_flag` | 高位强势整理 | 强趋势延续 |
| `limit_up_shakeout` | 涨停后洗盘 | 短线形态 |
| `uptrend_limit_down` | 上升趋势跌停错杀 | 反转/错杀 |
| `rps_breakout` | 相对强度 + 高位突破 | 强势股 |

优势：

- 技术逻辑清晰，适合作为强技术候选源。
- 和 AlphaSift 的 YAML 多因子互补。
- 对短线/波段候选更敏感。

不足：

- 偏技术和动量，弱市容易召回“看起来强但容易追高”的股票。
- 对资金、基本面、消息风险没有先验约束。
- 策略有效性还没有按市场环境动态调权。

### 1.3 其他候选源

| 来源 | 当前状态 | 定位 |
| --- | --- | --- |
| 板块主题 | 可从强势板块扩散到成分股，但接口稳定性一般 | 补充候选 |
| 消息事件 | 可从公司级新闻/公告召回个股 | 补充候选，不应压过硬策略 |
| 情绪/宏观事件 | 更适合输出主题观察 | 未验证前不直接推个股 |
| 资金面 | 当前更多用于候选后验证 | 需要升级为全市场发现 |
| 基本面 | 当前更多用于候选后验证 | 需要升级为全市场发现 |
| fallback seed | 固定观察池 | 只兜底，不算策略候选 |

## 2. 关键问题

### 2.1 候选池主干不应该被消息面覆盖

消息面能发现短期事件，但容易产生三个问题：

- 新闻已经被价格反映，后续没有弹性。
- 搜索结果和股票相关性不稳定。
- 宏观/主题事件不能直接推出个股。

因此候选池必须采用：

```text
硬策略候选为主
+ 资金/基本面候选补强
+ 消息/板块/情绪作为补充或观察
```

### 2.2 资金面还不是真正的发现专家

当前 `capital_heat` 主要用成交额、换手率、量比等流动性代理。真正的资金发现应覆盖：

- 个股主力净流入。
- 5/10 日资金持续流入。
- 行业/概念板块资金流。
- 龙虎榜/游资活跃。
- 融资买入和融资余额变化。
- 人气榜和涨停池作为短线情绪辅助。

### 2.3 基本面发现能力不足

当前价值策略主要看估值和市值，缺少：

- 营收增长。
- 净利润增长。
- ROE、毛利率、净利率。
- 经营现金流。
- 业绩预告。
- 回购、增持、减持、解禁、质押。
- 机构持仓变化。

这会导致“低估值”不等于“高质量”，“便宜”不等于“值得进入候选池”。

### 2.4 缺少策略回评和动态权重

候选池当前更像静态规则集合，还没有形成：

- 每日候选落库。
- T+1/T+3/T+5/T+10 表现回评。
- 按策略统计命中率、平均收益、最大回撤。
- 按市场环境调整策略权重。
- 自动降低近期失效策略的候选权重。

没有这层闭环，策略会长期停留在“看起来合理”，但不知道真实效果。

### 2.5 缺少候选池质量评估标准

P3 回评不能只统计单只股票表现，还要回答“本轮候选池是不是一个好候选池”。建议至少定义以下指标：

| 指标 | 含义 | 用途 |
| --- | --- | --- |
| 覆盖率 | 候选池是否覆盖当前市场主要机会，例如 T+1/T+3 涨幅 Top20 中有多少曾进入候选池 | 衡量召回能力 |
| 精准率 | 候选池中最终被 L2/Judge 通过的比例 | 衡量候选质量 |
| 多样性 | 行业、风格、市值、策略来源分布是否过度集中 | 避免单一风格失效 |
| 时效性 | 新进入候选、连续 N 天在池、即将过期候选的比例 | 区分新机会和老观察 |
| 负面命中率 | 候选在 T+3/T+5 内跌超 5% 或触发止损的比例 | 衡量候选池风险 |
| 有效转化率 | 候选进入深度分析后形成可执行 TradePlan 的比例 | 衡量 L1 对后续链路的贡献 |

没有这些指标，策略回评只能评价单个策略，却无法评价“候选池整体是否值得信任”。

### 2.6 缺少候选池生命周期管理

当前链路更像每次 Trace 从零生成候选池，但实际选股需要持续观察：

- 每次运行应生成本轮候选池，同时写入持续观察池。
- 连续多日命中的股票应提高“稳定性/持续性”标签，但不能无条件加分，必须结合价格是否已经透支。
- `valid_until` 过期后默认降权；若仍被策略重新命中，则刷新有效期。
- 连续 N 天未被任何来源命中、且无持仓/用户关注关系的候选，应自动移出观察池。
- 用户连续问“下周买什么”时，候选池不应完全失忆，应展示新进入、继续观察、降权移出三类变化。

建议候选状态至少包含：

| 状态 | 含义 |
| --- | --- |
| `new` | 本轮首次入池 |
| `active` | 仍在有效窗口内，且近期被策略或证据支持 |
| `watching` | 证据不足但仍有观察价值 |
| `decayed` | 有效期过期或热度下降，仅保留弱观察 |
| `removed` | 触发硬排除、过期过久或风险过高 |

### 2.7 缺少去重、共振和冲突处理规则

同一只股票可能同时被 AlphaSift 选为价值候选、被 Sequoia 选为突破候选、被资金专家选为流入候选。入池阶段不能生成多张重复候选卡，应按股票代码合并：

- `code` 是唯一键，名称由股票主数据统一覆盖，禁止跨阶段名称漂移。
- `recall_sources` 保存所有命中的专家/策略来源。
- `entry_reasons` 合并每个来源的入池理由，按贡献分排序。
- `supporting_evidence` 保存支持信号。
- `counter_evidence` 保存反证，例如技术突破但资金流出。
- 入池阶段不做最终冲突裁决，只标记多源命中、反证和数据质量；冲突裁决交给 L2/Judge。

共振加分不应只看“命中来源数量”，而应考虑来源置信度：

```text
consensus_bonus = min(15, sum(source_confidence * 5 for source in supporting_sources))
```

如果一个专家 `support`、另一个专家 `oppose`，候选仍可入池，但必须标记为 `mixed_evidence`，并在前端显示“存在反证，等待 L2 验证”。

### 2.8 缺少硬排除层

所有专家之前应有一层硬排除，不允许任何候选源绕过：

- ST / *ST / 退市风险。
- 停牌中或长期无有效成交。
- 上市不足配置天数的高风险次新股，除非用户明确允许短线次新策略。
- 日均成交额低于最低门槛。
- 极端一字涨停/跌停导致无法成交。
- 被系统风控标记为黑名单、历史异常或数据质量长期不可信。
- 股票代码/名称主数据无法校验一致。

硬排除层的输出应在 Trace 中可见：被排除的股票数量、原因分布、典型样例。否则用户无法判断候选池是“没机会”还是“被过滤掉了”。

### 2.9 缺少候选池和用户持仓/报告意图的关系

不同报告意图下，候选池入口不同：

| 意图 | 候选池来源 |
| --- | --- |
| `watchlist_scan` / “下周买什么” | 全市场候选发现 + 持续观察池 |
| `position_review` / 持仓诊断 | 用户持仓优先，不应全市场随机选股 |
| `rebalance` / 调仓 | 用户持仓 + 全市场替代候选 |
| `single_stock_entry` / 单股入场 | 用户指定股票，不需要 L1 全市场候选 |

用户已持有股票应进入独立通道：

- 持仓股若命中策略，标记为“持仓命中”。
- 持仓股不命中策略，也应作为“持仓诊断候选”进入风险复核，而不是被候选池过滤掉。
- Judge 最终排序时要区分“新买入候选”和“已有持仓处理建议”，避免把持仓诊断误写成新开仓推荐。

## 3. 目标架构

### 3.1 L1 候选发现

每个候选专家独立 `discover`：

| 专家 | discover 目标 | 是否必须出候选 |
| --- | --- | --- |
| AlphaSift 策略多因子专家 | YAML 多策略硬筛 | 是 |
| Sequoia 技术形态专家 | 技术形态/突破/RPS | 是 |
| 资金发现专家 | 主力、龙虎榜、两融、板块资金 | 是，待实现 |
| 基本面发现专家 | 成长、质量、估值、安全边际 | 是，待实现 |
| 板块主题专家 | 强势板块扩散到个股 | 可选 |
| 消息事件专家 | 公司级硬事件 | 可选 |
| 情绪/宏观专家 | 主题观察和验证线索 | 默认不直接推个股 |

### 3.2 候选池容量控制

建议默认候选池规模：`8-12` 只，采用“软配额 + 硬上限”，不做机械固定配额。

建议初始软配额：

| 来源 | 最小保底 | 最大数量 | 说明 |
| --- | --- | --- | --- |
| AlphaSift | 2 | 4 | 主干候选 |
| Sequoia | 2 | 4 | 主干候选 |
| 资金发现 | 1 | 3 | 实现后作为强补充 |
| 基本面发现 | 1 | 3 | 实现后作为中线补充 |
| 板块主题 | 0 | 2 | 只在板块数据可靠时补充 |
| 消息事件 | 0 | 2 | 只允许公司级硬事件 |
| 情绪/宏观 | 0 | 1 | 未验证时只进主题观察 |
| fallback | 0 | 0 | 只在候选为空时展示观察池 |

合并和截断规则：

- 先满足 AlphaSift / Sequoia 等硬策略主干的最小保底。
- 在总池未满时，按 `final_score` 填充其余候选。
- 单一来源不得超过自身最大数量，避免消息面或单一技术策略垄断候选池。
- 如果某个来源当天只有 1 只高质量候选，不强行补满配额。
- 如果 AlphaSift 今日只筛出 1 只，而 Sequoia 筛出 10 只，可以让 Sequoia 在硬上限内补位，但前端要显示“AlphaSift 供给不足”。
- 消息/情绪候选必须有事件日期、有效窗口和价格反应检查，否则只能进入主题观察。
- 如果 AlphaSift 和 Sequoia 都失败，必须标记为 `hard_strategy_trunk_missing`，不得把 fallback 或纯消息候选展示成完整候选池。

### 3.3 L2 统一验证

所有入池股票进入同一套验证流程：

```text
行情/流动性
-> 技术结构
-> 资金筹码
-> 基本面质量
-> 消息事件
-> 市场环境
-> 组合风控
```

注意：候选来源只说明“为什么值得看”，不说明“可以买”。最终动作必须由验证和 Judge 决定。

### 3.4 L3 Judge 排序

Judge 不直接相信任何单一来源，应按以下原则排序：

- 多维共振高于单维极端。
- 硬策略 + 资金确认优先。
- 技术强但资金反向应降权。
- 消息候选如果价格已经反应，应降权。
- 基本面缺失或质量差，不能给中线高置信。
- 市场环境 unknown/risk_off 时整体降档。

## 4. 优先级路线

### P0：修正候选池主干

目标：确保 AlphaSift / Sequoia 稳定进入候选池，不被消息面覆盖。

验收：

- `discover_watchlist_candidates(auto)` 输出中稳定包含 AlphaSift 和 Sequoia 候选。
- 前端清楚展示各来源配额和入池原因。
- 消息候选不能单独占满候选池。

### P1：实现资金发现专家

目标：资金面从“后验验证”升级为“全市场候选发现”。

候选规则示例：

- 近 5 日主力净流入为正，且 10 日不明显反向。
- 当日/最近交易日资金流入排名靠前。
- 板块资金流入与个股资金流入同向。
- 龙虎榜/游资活跃但不过度一致性买入。
- 融资买入增加但非异常杠杆堆积。

数据获取方案：

| 方案 | 做法 | 优点 | 风险 |
| --- | --- | --- | --- |
| A. 收盘后全市场预计算 | 每日 15:30 后批量拉取全市场资金流、龙虎榜、两融和板块资金，写入本地表 | 最完整，Trace 时只查库 | 接口配额、批处理耗时和失败补偿成本高 |
| B. 候选后验证 | 只对 AlphaSift / Sequoia / 板块候选拉取资金数据 | 成本低、稳定 | 不能独立发现资金异动股票 |
| C. 资金排行榜召回 | 使用 StockAPI/Tushare 可用的资金流入、龙虎榜、人气、涨停池 TopN 接口 | 最适合 P1 快速落地 | 依赖榜单接口权限和稳定性 |

P1 建议先采用 `C + B`：

- 使用排行榜类接口生成资金候选头部池。
- 对硬策略候选补拉个股资金做验证。
- 暂不在 Trace 运行时实时扫描 5000+ 只股票。
- 后续在 P3/P4 再补方案 A 的收盘后预计算任务。

验收：

- 资金专家可独立输出候选。
- 每只候选给出资金来源和有效日期。
- 资金候选进入前端独立分组。

### P2：实现基本面发现专家

目标：补齐中线和稳健风格候选。

候选方向：

- 低估值 + 稳定盈利。
- 高 ROE + 增长稳定。
- 业绩预增 + 估值未透支。
- 回购/增持 + 基本面不差。
- 现金流健康 + 板块不过热。

数据获取方案：

- 基本面发现不应在 Trace 运行时实时拉取全市场财报。
- 应建立本地预计算表，按财报披露、参考事件和交易日增量更新。
- Trace 只查询预计算结果，再对少量候选做补证。

建议表结构：

| 表 | 关键字段 | 更新频率 |
| --- | --- | --- |
| `fundamental_snapshot` | `code`、`report_period`、`roe`、`gross_margin`、`net_margin`、`revenue_growth`、`profit_growth`、`operating_cashflow_ratio`、`debt_ratio`、`pe_ttm`、`pb` | 季报后更新，周级补齐估值 |
| `fundamental_events` | `code`、`event_type`、`event_date`、`direction`、`amount`、`summary`、`source` | 每日 |
| `shareholder_events` | 回购、增持、减持、解禁、质押、股东变化 | 每日 |
| `institution_snapshot` | 机构持仓、评级、盈利预测变化、覆盖家数 | 周级或月级 |

P2 的核心不是“实时查到所有财务字段”，而是让候选理由能写出具体指标，并让缺失数据明确降权。

验收：

- 基本面专家可独立输出候选。
- 候选理由包含具体财务指标，而不是只写“估值低”。
- 基本面候选和趋势候选在前端分组展示。

### P3：策略回评和动态权重

目标：让策略池从静态规则变成可评估系统。

回评窗口：

- T+1。
- T+3。
- T+5。
- T+10。

指标：

- 平均收益。
- 超额收益。
- 最大回撤。
- 胜率。
- 入池后是否触发止损。
- 是否被 Judge 最终否决。

验收：

- 每日候选池落库。
- 可按策略查看历史表现。
- 最近表现差的策略自动降权。

### P4：Regime 动态策略权重

目标：不同市场环境使用不同候选偏好。

示例：

| 市场环境 | 候选偏好 |
| --- | --- |
| 趋势向上 | 提高 Sequoia / momentum / breakout 权重 |
| 震荡 | 提高 shrink_pullback / balanced_alpha 权重 |
| risk_off | 降低追涨策略，提高 value / defensive 权重 |
| 高波动 | 禁止纯突破追涨，优先等待确认 |
| 市场未知 | 降低所有开仓动作，增加验证要求 |

Regime 来源：

- 主来源：`detect_market_regime` 工具输出。
- 辅助来源：指数趋势、市场宽度、成交额变化、板块扩散、融资融券、北向/市场资金代理数据。
- 人工覆盖：允许通过配置指定临时 regime，但必须在 Trace 中显式展示为 `manual_override`。

保护机制：

- `unknown` / `insufficient_data` 时不允许提高进攻型策略权重，只能维持或降权。
- 多个市场证据冲突时，regime 应降级为 `mixed`，不能强行判定趋势市。
- Regime 只能调整候选权重和验证要求，不能单独推出买入结论。
- 极端波动或 risk_off 下，即使技术候选分数高，也要提高 L2 验证门槛。

验收：

- 候选合并时能看到 regime 权重调整。
- 前端显示“因市场环境调整策略权重”的理由。

### P5：消息/情绪候选治理

目标：消息和宏观情绪只在合适场景进入候选，不再挤占硬策略主干。

规则：

- 公司级硬事件可以进候选。
- 宏观/地缘/政策事件默认只进主题观察。
- 事件必须有有效窗口。
- 需要检查价格是否已经反应。
- 负面事件优先作为反证，而不是候选。

验收：

- 消息候选数量被限制。
- 主题观察和个股候选在前端分开展示。
- 新闻候选必须展示事件日期、来源、有效窗口和是否已价格反应。
